### 文档治理规则（本项目强制执行）

1. **规格卡由交付方出，冻结即唯一真值源**，同文同版本号发给所有下游（策划配表 / 技术单测 / 美术外包）。一人发两张卡是流程错误，不是协作分歧。
2. **跨域数字只认规格卡与单测里的版本**，口头修订、消息里的临时说法一律无效。
3. 任何改动走**变更单**：改哪一项 / 为什么 / 影响哪些断言 / 谁复核。
4. **能去耦的争议不裁决**：资产元数据（剪辑长度、面数、贴图规格）一律由管线注入，不写成配表常量、不进口头裁定。所有"资产元数据 × 策划数值"的耦合字段都按此处理。
5. **环境会变的量，不许写死**。凡取值依赖环境（背景亮度、频率、分辨率、设备档位、窗口长度、帧率）的常量，必须写成**推导式或环境参数**。本项目已五次命中同一类错误：受击帧数（应引用 `anim_clip_length`）、词条绝对值（应存系数）、脉冲阈值 250ms（应为 `1000 ÷ 2×hz`）、墨线与压边固定墨黑（应按背景亮度差推导）、击退速度写 `m/帧`（应为 `m/s`，否则 30fps 下直接翻倍）。**且多参数组合的极值必须验算**：单参数合法不等于组合合法（距离 ÷ 帧数、分辨率 × 缩放、面数 × 同屏数），要用**最坏组合**算物理量，并把最坏情况锚在项目的最低硬件档而非目标档。**且调参必须复验它影响的所有派生量**：距离上调 → 后段总量上调 → 峰值同比例上调 → 30fps 红线重新逼近——**"只改一个参数"不等于"只在改一处"**（重档从 1.5m 试到 1.6m 就是此例：6% 余量够跑，但不该为 10cm 花掉一半安全边）。
6. **阈值不是从"够"推出来的，是从"坏了"倒推出来的**。定 8 帧前摇，不是问"8 帧够不够"，而是问"压到 5 帧，若 5/5 测试者仍报'有分量'，说明 8 帧不是必要值"。每条判据都要能写出这个倒推过程。
7. 数据归属见**附录 C 真值源清单**，评审时谁改数都有据可依。
8. **禁止另行发散"全文副本"**。同一份规格只维护一份正本，修订以「引用 + 差异」发布，不发重排全文。**冗余的副本比缺失的信息更容易害人**——多一份全文，下一个人就会在两份之间挑，然后"唯一真值源"再次失效。同理：**批准必须写明被批准的版本号，版本号不存在则退回**（本轮出现过"工程批准了已被替代的卡"）。
9. **任何判据必须声明量纲**：m / m/s / 帧 / 毫秒 / **哪一根时钟的帧**。拿不同量纲的量相减或相比，结论永远是假的——本轮三次翻车是同一件事的三个变种：`m/帧` vs `m/s`、**剪辑帧 vs 墙钟帧**、占屏比例 vs 遮挡比。
10. **时间量一律写 `T_xxx`（elapsed，`t=0` 在命中帧），帧号只用来标识对象、禁止参与算术。** 帧号自带两层约定（0/1 起点、含不含首尾），只要拿它做加减就必然差 1——本轮同一处一帧差滑了五次、五人次，根因不是粗心而是表示法。**换算规则：帧 `i` 覆盖 `[i, i+1)`，`i` 是入点；"第几帧"永远指入点，问"什么时候结束"必须用 `i+1`。求两段之间的空档，两端必须都用时刻，不能用索引。**
11. **文档里不得出现第二个合法值**（含"预设备选值""可选上调档""暂定值"）。写进正文的数值只能有一个；被否决但算过的值，只能以「算过、未采用」的形式留在记录里，不得留成可填的备选。**否则 W4 有人想放宽时不必走变更单，只要引用"文档里写着可选"就能直接改**——这比暗中偏移更难拦，因为它有书面依据。
12. **上限要写成因果式，不写成常数。** 例如顿帧上限应写 `0.15 × hitstop_frames ≤ 1`（推出整数上限 6），而不是 `hitstop ≤ 6`——前者在 `time_scale` 调低时自动放宽，后者会变成凭空卡人的常数。**这正是本项目杀掉一整轮的那类常量，不要在收口处又请回来。** 同理：`3 − 0.15h ≥ 2` 里的 `3` 应写成 `(收身起始进度 − 后段窗口帧数)`，否则收身从 C10 挪到 C12 时会静默算错。
13. **公式定案前，拿一个已知边界反代一次。** 若反代结果与已知边界矛盾 → 公式错；自洽 → 才拿去定阈值。**它与"证伪案例"同族但验的对象不同：证伪案例验判据，端点反代验公式。** 本项目十几次数值滑动，全部发生在"公式没被反代过"的地方。
14. **错误的处置办法比没有处置办法更危险。** 若规范写了"想加顿帧就延硬直"，而公式里根本没有 `hitstun_frames`——半年后有人照做、断言照挂，会判断"断言坏了"，然后去改断言。**规范只描述事实，不提供未经推导的处置手段。**
15. **同一规格只在一处描述，其余位置只引用不复述。** 需要指代时写「见 §X」，不要抄一遍数值。**复述即制造第二个来源**——本轮「无敌长什么样」在文档里同时存在三份（§7.2 已改对、附 A 与 §8.5 仍留旧写法），改一处等于没改；而它在可访问性章节里，最容易被评审当成我们的承诺。同理，任何规格变更后的收尾动作是**全局搜关键词**，不是只改你记得的那一处。**且搜索范围必须含"旧表述"**——变更日志、历史版本说明里那句被推翻的结论，会以「历史事实」的口吻误导读者，比规格写错更隐蔽。本轮「无敌 2Hz 脉冲」一共在四处存活：§7.2（早正确）、附 A、§8.5、变更日志 **v0.3→v1.0 条目**；前三处描述当前状态、第四处描述历史。**改规格时人们搜的是"当前规格在哪"，而不是"哪里提到过它"，所以第四处必漏。**

> **v0.3 → v1.0 主要变更**：受击帧数彻底去耦（文档与配表均不写死帧号，改引用剪辑长度）；D1b 的"方向"判据移交给 D2（归工程、8 向含斜向）；无敌表现：**初版拟用 2Hz 脉冲，后因回锋无敌窗口仅 5 帧（83ms）容不下 500ms 周期，改为纸白双边描边 + 入窗高亮 1 帧**（见 §8.5）；玩家特效一律不落地、地面形状通道由敌人独占；`Mark_Elite` 改为实绘占位块；新增附录 C 真值源清单。

## 0. 一句话概念与项目边界

**一句话概念**：一个落魄刀客在五处残破江湖遗迹里反复闯本、拾取断锋残页，靠六条互不替代的修为线一点点把自己"修"回来的单机 3D 动作 RPG。

**核心体验承诺**：每一次进本，你都带着一个明确的"我要变强哪一点"，出本时这三点真的变了，并且立刻能打一个之前打不过的本。

### 0.1 做什么 / 明确不做什么

| 做什么（MVP 内） | 明确不做（本代一律不出） |
|---|---|
| 5 个线性解锁副本，单局 6–16 分钟 | 开放世界、无缝大地图、任意顺序探索 |
| 1 个可选主角，1 套轻量动作组（3 段普攻 + 2 技能 + 闪避） | 多职业、多角色、连招树、招式派生、天赋树分叉 |
| 6 条修为线并行养成，可自由分配 | 完整肉鸽（随机地图 / 随机构筑 / 局内成长） |
| 1 套 3 部位装备 + 18 条随机词条 | 装备强化 / 洗练 / 镶嵌 / 套装 / 附魔等二级系统 |
| 1 个主城营地（单场景） | MMO、联机、公会、拍卖行、赛季 |
| 本地存档、单周目 11–14 小时 | 服务器、账号体系、云存档、排行榜 |
| 3 类敌人 + 1 个 Boss | 长线运营、海量剧情、多结局、配音过场 |
| 文字驱动的极简叙事（每副本 3–5 条文本） | 电影化演出、面部捕捉、支线任务网 |

**边界铁律**：任何新增系统必须先回答"它能否让玩家在第 30 分钟、第 3 小时、第 9 小时各感受到一次明确变强"。答不上来的，进第 14 章，不进 MVP。

## 1. 目标玩家与 3 条体验支柱

### 1.1 目标玩家画像

| 维度 | 描述 |
|---|---|
| 是谁 | 25–35 岁、玩过动作 RPG 与刷宝游戏、现在每周只有 6–8 小时游戏时间的上班族 |
| 设备 | 一台 1080p 的轻薄本或三年前的独显游戏本，不追求光追 |
| 什么时段玩 | 工作日晚上 1 次（40–70 分钟）、周末 1 次（2–3 小时连玩） |
| 为什么玩 | 想要"目标明确、单局可控、进度看得见"的爽感；受不了开放世界的空虚和联机的社交压力 |
| 玩多久 | 单周目 11–14 小时，愿为 68–98 元买单（若上架） |
| 最怕什么 | 打不动 → 不知道该刷什么 → 关掉不再打开 |

### 1.2 三条体验支柱

| 支柱 | 设计上如何落地 | 如何验证 |
|---|---|---|
| **P1 每一刀都有回响**（打击感优先于招式数量） | 只做 3 段普攻 + 2 技能 + 闪避，但每条动画都给足 ≥8 帧前摇、20 帧受击硬直、命中 3 帧内出反馈（顿帧 0.06s + 屏幕微推 + 音效） | W4 Gate 1：21 条走查表 ≥17 条"可接受"，否决项见 10.1 |
| **P2 我知道下一步该刷什么**（进度透明） | 每次结算直接标出"离下一条修为线还差 X 个材料"；副本列表常驻"战力差 + 一个箭头"；营地有"推荐去处"高亮 | W13 盲测：新玩家 90 秒内自行说出"我下一步打哪个本"的比例 ≥80% |
| **P3 变强是看得见的**（数值可视化） | 修为升级有明确的战力数字跳动；同一副本在战力跨门槛后，通过时间从 13 分钟压到 8 分钟 | W15 试玩：80% 玩家能复述"我从打不过到打过用了多久" |

## 2. 核心循环

| 层级 | 时长 | 循环链路 | 玩家在重复什么 | 变化点在哪 |
|---|---|---|---|---|
| **分钟循环** | 30 秒–3 分钟 | 锁定敌人 → 普攻 3 段 / 技能 → 闪避穿招 → 拾取 → 推进下一波 | 同一套 5 个动作 | 敌人组合（刀客贴身 / 弓手远程 / 术士控场）逼出不同的技能优先级 |
| **小时循环** | 30–90 分钟 | 选本 → 清怪 → 精英 → Boss → 结算 → 回营地升修为 / 换装备 → 战力上涨 → 解锁下一本 | 同一批副本 | 战力跨门槛后同一副本的通过时间与容错率变化；词条随机带来装备替换 |
| **长期循环** | 11–14 小时（单周目） | 五本首通 → 六线 Lv10 → 词条毕业 → 孤锋崖通关 | 26 次有效副本 | 材料分级抬升（凡→良→珍→秘→传说）、卡点从"打得慢"变成"打得过" |

**循环的硬设计**：每 30 分钟必须发生一次"战力数字变大"，每 90 分钟必须解锁一个新东西（新本 / 新修为线档位 / 新词条位）。若某段 90 分钟里两者都没发生，视为数值设计失败，W13 必须返工。

## 3. 单局副本结构

| 阶段 | 时长 | 玩家动作 | 情绪目标 | 失败处理 |
|---|---|---|---|---|
| 进入 | 10–20s | 营地选本 → 读 1 条文本 → 落地 | "这次要拿什么" | — |
| 清怪（2–3 波） | 3–6min | 3–5 只小怪组合，练锁定切换与闪避 | 熟练、节奏感 | 死亡则从本波起点复活，保留已拾取材料 |
| 精英 | 2–4min | 1 只 1.4 倍放大的同类精英，有 1 个额外机制 | 第一次紧张 | 同上 |
| Boss | 3–6min | 孤锋崖专属；其余副本以"精英收尾"替代 | 高压峰值 | 死亡则回 Boss 门前，Boss 满血 |
| 结算 | 10–20s | 材料入包 + 战力差提示 + 推荐下一步 | 获得感 | — |
| 养成 | 1–3min | 回营地升修为 / 换装备 / 看词条 | 变强的确认感 | — |

**MVP 取舍**：先做"线性波次 + 定点刷怪"，暂时砍掉随机地图布局、动态难度、隐藏房间、限时挑战。落霞渡作为教学本无 Boss，用 2 波小怪 + 1 精英收尾，把"锁定 + 闪避"两件事教完。

## 4. 修为系统

### 4.1 六条线

| 修为线 | 作用 | 主属性 | 材料来源 | 上限 | 卡点设计 |
|---|---|---|---|---|---|
| **淬骨** | 生命上限、受击减伤 | 体魄 / 防御 | 铁砧窟（矿石类） | Lv10 | 卡 Lv5：需珍品「寒铁」，仅铁砧窟精英 12%；卡 Lv9：需秘品，仅断碑古刹 |
| **气海** | 技能伤害、内力回复 | 内功强度 | 落霞渡 / 雾隐竹海（草药类） | Lv10 | 卡 Lv4：需良品「灵犀草」，落霞渡掉率偏低，倒逼回头刷 |
| **身法** | 移速、闪避冷却、攻速 | 敏捷 | 雾隐竹海（禽羽类） | Lv10 | 卡 Lv6：需珍品「风隼羽」，雾隐竹海精英专属；每级 −0.1s 闪避冷却，Lv10 触底 2.5s |
| **锋锐** | 普攻与技能基础伤害、暴击 | 攻击 | 各本通用（断锋石） | Lv10 | 全程平滑，是"永远有得升"的兜底线，但单位战力权重最高、成本也最高 |
| **心印** | 掉落率 +、拾取范围、材料转化 | 悟性 | 断碑古刹（残页类） | Lv10 | 卡 Lv3：首通断碑古刹才解锁该线，前期不可投 |
| **名望** | 商店折扣、解锁推荐、额外保底次数 | 江湖声望 | 通关与首通计数（不占背包） | Lv10 | 靠"次数"而非"材料"，是防卡死的安全阀 |

### 4.2 战力公式

```
战力 CP = 120（角色白值）
        + 1.0 × 淬骨原始值
        + 1.2 × 气海原始值
        + 0.9 × 身法原始值
        + 1.3 × 锋锐原始值
        + 0.6 × 心印原始值
        + 0.4 × 名望原始值
        + 装备战力（基底 + 词条）
```

- **单线每级原始值**：Lv1–5 每级 +50，Lv6–8 每级 +70，Lv9–10 每级 +110（单线满级累计 680）
- **权重总计 5.4**：六线全 Lv10 的修为战力 = 680 × 5.4 = 3672
- **权重含义**：锋锐（1.3）> 气海（1.2）> 淬骨（1.0）> 身法（0.9）> 心印（0.6）> 名望（0.4）。输出线权重最高，感悟类最低，避免"刷掉落"变成最优解

### 6.2 装备与词条

3 部位（武器 / 衣 / 坠）× 5 品阶，词条池 18 条（攻击、暴击、闪避冷却、材料掉落、受击减伤等），每件随机 1–3 条，数值按品阶区间浮动。装备战力 = 基底（白 20 / 绿 45 / 蓝 90 / 紫 150 / 金 220）+ 词条加权。

| 机制 | 触发条件 | 规则 |
|---|---|---|
| 材料保底 | 同一副本连续 3 次未出目标珍品/秘品 | 第 4 次必出 1 件（`pity_threshold=3`，`pity_window=3`） |

| 战力校验 | 战力低于副本门槛 10% 时进本 | 结算材料量 +25%，避免"打不过又没得升"的死锁 |

### 6.4 重复刷的五个动机

1. **卡点材料**：Lv5 / Lv8 / Lv10 三处硬卡点，必须回头刷特定本
2. **词条替换**：同一部位出更好的词条组合，18 条池子保证 20 小时内不重复
3. **首通奖励差异**：首通给解锁与大量材料，复刷给稳定的低级材料，两种价值不冲突
4. **名望进度**：通关次数直接换折扣与兑换额度，刷本本身有确定性收益
5. **时间压缩快感**：战力跨门槛后同一副本从 13 分钟压到 8 分钟，重复本身成为"变强的证据"

> **时钟轴约定（本节与 §9.4 通用）**：`W` = **墙钟帧**（硬直 / 顿帧 / 位移窗口 / hold / 取消窗口）；`C` = **剪辑帧**（姿态 / 收身 / 首尾双稳定 / 受击变体）。**所有时间量写 `T_xxx`（elapsed 帧，t = 0 在命中帧）；帧号只用于标识对象，禁止参与加减。** 帧 `i` 覆盖区间 `[i, i+1)`——「起始帧」一律指该帧**入点**（进度 = 帧号 − 1），问「什么时候结束」必须用 `i+1`；求两段之间的空档时，两端必须都用时刻，不能用索引。

**受击剪辑：只约束结构，不约束帧数**

| 约束 | 内容 |
|---|---|
| 长度 | 剪辑 **≥12 帧**（当前交付 13 帧，帧号属资产元数据，配表与断言均不引用） |
| 首尾双稳定 | **首尾两帧均须稳定可保持**（重心落双脚之间、无极限伸展、肩线不被挂件遮挡），首段与末段相邻帧间差各 ≤3° |
| 两层位移分离 | ① 代码击退 1.2–1.5m，于剪辑**前段**完成并归零；② 动画内脚掌回位 ≤8cm，于**后段**回至 0。两层不冲突，但回位必须有，否则 hold 段微晃退化为原地抖 |
| 顿帧语义（D4） | **击退起于命中帧、贯穿顿帧；顿帧把动画速度降到 15%，不冻结位移曲线。** 引擎参数 `hitstop_time_scale = 0.15`。用 0（完全冻结）会"立着滑出去"；用 1（不减速）没有卡住的手感；只有 0.15 能同时给出"卡住了"与"被顶开"，且受击卡一个字段都不用改 |
| 减速 | timeScale 0.7 **仅作用于最后 3 帧**（更早会吃到位移插值致脚底打滑） |
| 逻辑时长 | **硬直按击退档位取 18 / 20 / 22 帧**（轻 / 中 / 重），配顿帧 2 / 4 / 6 帧、**hold 时长 3.3 / 3.6 / 3.9 帧**——三档全部落在 2–4 帧规格内，动画无需任何提速。20 帧档的配平算式：14 帧墙钟内需装 12.4 帧动画 + 5 帧 hold，18 帧只剩 1.6 帧余量、跌破 2 帧下限，故取 20。**hold 起始引用剪辑长度，不硬编码**。**另配硬断言 `hold ∈ [2, 4]`**——公式是给算的人看的，断言是给改的人拦的：18 帧方案装不下这件事本是靠手算才发现，有了断言就是导表自动报错 |
| 击退分档 | **轻（普攻 1）0.3–0.6m ／ 中（普攻 2、回锋）0.8–1.2m ／ 重（普攻 3、破锋）1.2–1.5m**。不分档会让玩家被 Boss 连段一路推着走、站位失控——这是可玩性错误，不是数值优化。重档上界取 1.5m：2.0m 在 **30fps 下限**等于每帧 0.586m（≡1.2 个身位），读出跳帧感；1.5m 为 0.44m/帧、峰值 13.2 m/s，留 12% 余量。拉长后段窗口不可行——会撞上收身段，变成"一边收身一边滑"。**"打飞感"不只靠距离，靠顿帧 6 帧 + 后仰 15° + 硬直 22 帧三样一起给**。**D2 判据优先级（互斥时必须写死，否则玩家在墙边被打时挂测试而实际表现最对）**：不被推入墙内 / 不推落平台 **＞** 方向一致 **＞** 距离达标 |
| 曲线形状 | **`split_frame` 必须等于各档顿帧帧数（2 / 4 / 6），不能三档共用**——"前段"的定义就是顿帧期间；轻档只顿 2 帧却在 4 帧里缓行，会读成"卡一下、晃两下、再飞"。**唯一真值源是帧索引区间，不是总帧数**：前段 = F0 … F(hitstop−1)（正好 hitstop 帧），后段 = F(hitstop) … F(hitstop+5)（**固定 6 帧** ease-out）。`front_ratio`=0.12，前段走 12%（"被顶住"）→ 顿帧结束即达峰值 → 后段衰减至 0。**禁止"先加速后减速"**，后段一开始就得是峰值，否则"被打飞"的爆发感消失 |
| 三个口径陷阱 | ① **不要存"总帧数"**：美术记 8/10/12、策划记 9/11/13，差 1 全因"含不含首尾"——要记就记"前段 = hitstop 帧、后段 = 6 帧"两个区间。② **"前段 F0–F4"是 5 帧而顿帧只有 4 帧**（off-by-one），会让 W4 量窗口时多出一帧、被误判成"位移拖尾"。③ **帧号必须带时钟标签，且换算用时间戳不用帧号**：`W` = 墙钟帧（硬直 / 顿帧 / 位移窗口 / hold / 取消窗口）、`C` = 剪辑帧（姿态 / 收身 / 首尾双稳定），**`t(C_i) = (i − 1)` 帧**。顿帧把动画拖慢后两轴不再相等，跨轴相减必错。本例：位移窗口归零于 elapsed = hitstop+6；收身起始（剪辑第 10 帧）落在 elapsed = **9**，换算墙钟 = `hitstop + (9 − 0.15 × hitstop)`；**gap（位移归零→收身起始的空档）= 3 − 0.15 × `hitstop_frames`** → 轻 **2.7** / 中 **2.4** / 重 **2.1 帧**，三档都是位移先结束，**"重叠"从未存在**。这条闭式还自动推出**顿帧硬上限 ≤6 帧**（余量 ≥2 ⇒ 3 − 0.15×h ≥ 2），三档 2/4/6 正好用满边界；日后有人把顿帧调到 8，断言会自己挂。**断言按时刻写**：`T(位移归零) + 2 ≤ T(收身起始)` → 8+2≤10.7 ／ 10+2≤12.4 ／ 12+2≤14.1。**另注：本项目不存在"收身期间允许位移"的豁免条款；若观察到收身时仍在滑，应查 `curve_frames` 与 `knockback_dist`，而不是查豁免** |
| 变体 | **必须交付 4 变体（正向 / 反向 × 左右镜像），拆为 4 个独立交付项**，不合并成"受击动画"一行 |
| 反向变体失败条件 | **脚底接触点到地面垂直距离 >3cm 且持续 ≥2 帧**即判姿势不稳，退回重画。用几何量判定，不用目测——外包与 QA 不必为此争议 |

**两条动画硬指标**：① 闪避采「原地中性收身」（重心下沉 8–12cm + 双脚错开 ≤15cm + 躯干收 15° + 视线朝输入方向），**不做前倾、不迈步**，末帧与待机首帧姿势差 ≤5°，整条剪辑重心垂直位移 ≤10cm —— "冲出去"的手感全靠代码位移曲线（前 2 帧为蹬地窗口，位移 ≤5%），W4 用走查 C1 调曲线而非改动画；② 受击剪辑首尾两端稳定可保持，否则反向播放不成立。

### 7.4 敌人 AI 与场景复用

- **MVP 只做 3 类敌人**（共享 1 套骨架 + 4 条通用动画 + 各 2 条攻击）：刀客（近战压迫）、弓手（两档预警）、术士（范围控 + 减速）。
- **弓手两档**：瞄准 ≥24 帧 → ① 快射 12 帧，**不可躲**（逼玩家用走位/掩体），表现＝地面瞄准线；② 蓄力 ≥24 帧，可躲，表现＝地面预警圈。
- **精英标识**：`scale 1.4×`（**必须同步缩放受击盒与胶囊体**，仅缩渲染体会导致打不到，预制体上加注释级说明）+ 复制既有挂件 + Emissive 1.5×。刀客加披风（40 面，全表唯一真新增件，200 元）；术士双臂各挂 1 盏灯笼 + 原手持 1 盏＝3 盏（0 新资产）；弓手背挂 3 个箭筒（0 新资产）。
- **头顶标记**：两列配置 `elite_marker_enabled`（默认 0）+ `elite_marker_max_concurrent`（默认 2，防 8 敌同屏叠团）；UI 图集**预留并实际绘制** 32×32 纯色占位块 `Mark_Elite`——只留空索引等于没留，图集仍要重开。W7 盲测识别率 <70% 才开启。
- **场景模块**：1m 网格对齐，模块仅 2m / 4m / 8m 三级，墙高 4m、门洞 2×3m，全套 19 件（12 建筑 + 7 自然），每副本用 12–16 件 + 1 个唯一地标，按 4m 网格离线合并 chunk。差异化靠顶点色偏移、光照预设、雾效，不新增模型。

## 9. 技术方案

### 9.1 引擎选型对比

| 维度 | Unity 6 URP | Godot 4.x | UE5 |
|---|---|---|---|
| 许可与分成 | 优 年营收 20 万美元以下免费 | 优 完全免费、MIT | 中 超 100 万美元后 5% 分成 |
| 3D 动作工具链 | **优** 动画重定向/混合树/根运动/相机生态最成熟 | 中 3D 动画与重定向较弱，需自建 | 优 动画系统强但重 |
| 风格化低模表现 | **优** URP 下低模 + 描边很轻，性能好 | 优 性能轻，但描边需自写 | 劣 写实管线偏重，风格化反而费劲 |
| 团队上手成本 | 优 国内教程/招聘最多 | 优 上手快，但 3D 深水区文档少 | 劣 蓝图/C++ 双轨，小团队易踩坑 |
| 迭代速度 | 中 域重载后已改善，仍慢于 Godot | **优** 秒级热重载 | 劣 着色器编译/打包时间长 |
| 美术外包对接 | **优** 外包方几乎都接 Unity | 劣 多数外包不接 Godot 工程 | 中 接 UE 的外包偏写实向 |
| 国内招聘/资源 | **优** 最大 | 中 增长中 | 中 |
| PC 包体与性能下限 | 优 空包 ~60MB | **优** 空包 ~40MB | 劣 空包 ≥300MB |
| 12–16 周风险 | **低** | 中 3D 动作要自己搭轮子 | 高 学习曲线吃掉排期 |

### 9.2 推荐

**主选：Unity 6 + URP**。① 3D 动作游戏最贵的不是渲染，而是动画/相机/输入这三套轮子，Unity 有现成且成熟；② 本作大量依赖买资产包，Unity 兼容性最好；③ 外包方几乎都接 Unity 工程，返修成本最低；④ URP 在低模 + 描边 + 少量 VFX 下，集显轻薄本能稳定 30fps。

**备选：Godot 4.x**。适合"团队已有 ≥200 小时 Godot 经验、且不打算让外包碰工程文件"的情况。

**改选条件（可判断）**：主程有 ≥2 个 Godot 3D 项目经验，或预算严格为零 → 改选 Godot 4；主程有 3 年以上 UE 经验且追求写实演出 → 才考虑 UE5，否则 16 周内不出可玩版本。

### 9.3 存档与数据表

| 项 | 方案 |
|---|---|
| 存档格式 | JSON + 二进制头校验，单文件 `save_01.sav`，位于 `%USERPROFILE%\AppData\LocalLow\<公司>\<游戏>\` |
| 版本 | 头内写 `save_version`；MVP 只支持 v1，读到高版本拒绝并提示，不做迁移链 |
| 防篡改 | 仅 CRC + 关键字段上下限校验（单机够用，不做加密） |
| 自动存档点 | 结算完成、修为升级成功、装备穿戴变更、进出副本、退出游戏 |
| 坏档兜底 | 保留 `save_01.bak`；主档损坏自动回退并弹提示 |

**MVP 配置表 13 张**：`hero_base`、`cultivation_line`、`cultivation_level`（6 线 × 10 级 = 60 行）、`skill`（含帧数据与特效脉冲）、`enemy`、`boss_phase`、`dungeon`（含 4 列保底）、`drop_table`（一行一条，不设组表）、`equipment_base`、`affix_pool`（18 条）、`affix_curve`、`text_zh`、`audio_bank`。

**三条落表原则（决定平衡表会不会悄悄失效）**

| 原则 | 做法 | 不这么做的后果 |
|---|---|---|
| ① 资产元数据由管线注入 | `anim_clip_length` 从动画文件读取，不手填 | 三人各维护一份帧数，改一次要同步三处 |
| ② 只存系数，不存绝对值 | `affix_pool` 存"攻击 +8%"，不存"+37 点战力"；绝对值 = 基底 × 系数 | 一旦基底调平衡，全部词条数值作废 |
| ③ 平衡量存可断言单位 | `cultivation_level` 存 **`cost_eu`**（策划填这个），材料件数由 `cost_eu ÷ 单件 EU` 派生 | 有人改材料品阶折算（凡1/良3/珍9/秘27/传81），表内真实成本即与 624 EU 脱钩，第 4 章时长与门槛全部作废且**不报错** |

其余约定：配表内不写中文，全走 `name_key`；空档位留空串而非 0；`note` 列导表时剥离。

### 9.4 手感字段与导表断言

| 表 | 新增列 |
|---|---|
| `hero_base` | `anim_clip_length`（管线注入）、`knockback_front_ratio`(0.12)、`knockback_peak_speed`(≤18 m/s，且 **30fps 档每帧位移 ≤0.5m**——用最低帧率档做最坏情况校验，不用 60fps)、`dodge_total_frames`(22)、`dodge_move_frames`(16)、`dodge_dist`(3.2–3.6)、`dodge_cd_base`(3.5)、`fwd_final_offset`(≤0.05)。**受击 / 击退的四个时长字段已移入 `skill` 表**——它们是"招式打出去之后受击方的反应"，随招式走；同一 20 帧硬直套在轻击上就是错的 |
| `skill` | `vfx_pulse_hz`（**默认 0，MVP 不启用脉冲**）、`vfx_outline_px`、`vfx_outline_style`（0=单边实描 / 1=双边中空）、`armor_vfx_id`、`invuln_vfx_id`。取值：`pofeng` px=4 style=0；`huifeng` px=2 style=1。**受击 / 击退四字段按击退档位取三值**：`hitstun_frames`（轻 18 / 中 20 / 重 22，**唯一由策划手填的时长值**）、`hitstop_frames`（2 / 4 / 6）、`hitstop_time_scale`=0.15、`hitstun_hold_duration`（派生只读 = `hitstun_frames` − `anim_clip_length` − `hitstop_frames × (1 − hitstop_time_scale)` = **3.3 / 3.6 / 3.9**）、`knockback_split_frame`（**派生 = `hitstop_frames`，禁手填**）、`knockback_dist_min/max`（轻 0.3–0.6 / 中 0.8–1.2 / 重 1.2–1.5）、`knockback_curve_frames`（派生 = `hitstop_frames` + 6，即 8 / 10 / 12） |
| `cultivation_level` | `cost_eu`（策划填），材料件数派生 |
| `enemy` | `telegraph_frames`(≥24)、`telegraph_shape_id`、`telegraph_anim_id`、`telegraph_audio_id`（**四列独立，禁止塞 JSON**，否则无法逐列非空校验）；弓手建两行：`fast_shot_frames`=12 / `charge_shot_frames`≥24 |

> 脉冲频率放在 `skill` 而非 `hero_base`：脉冲是**特效属性**，只在具体技能的霸体/无敌窗口内发生，角色没有持久脉冲状态。同一量存两份，值不一致时会出现"以谁为准"的未定义行为。

**导表硬断言（12 条，任一不过即拦表报错）**

| # | 断言 | 拦的是什么 |
|---|---|---|
| 1 | `anim_clip_length ≥ 12` 且 `hitstun_frames ≥ anim_clip_length` | 资产交多少帧引擎都跟得住，无需三处同步改数 |
| 2 | `invuln_end ≤ dodge_move_frames ≤ dodge_total_frames` | 无敌溢出位移段 |
| 3 | `invuln_end − invuln_start ≤ 14`（0.23s 上限） | 无敌过长导致无脑闪 |
| 4 | `dodge_move_frames` 后残留位移 <0.05m | 收尾滑步 |
| 5 | **`T(位移归零) + 2 ≤ T(收身起始)`**，两端均为 **W 轴时刻**：`T(归零) = hitstop + 6`、`T(收身) = hitstop + 9 − 0.15 × hitstop` | 人已在播 hold，位移还在推。**旧写法 `curve_frames ≤ hitstun_hold_from` 跨 W/C 两轴（前者是墙钟帧数、后者是剪辑长度），8 ≤ 13 只是碰巧通过，语义不成立——已作废** |
| 6 | **必要条件**：`armor_vfx_id ≠ invuln_vfx_id` **且** `vfx_outline_style` 不同（`single_solid` vs `double_hollow`）。`vfx_outline_px` 差 ≥2px、`vfx_pulse_hz` 不同**仅作记录，不参与判定** | 原写法"三选一 OR"有洞：两个都是单边实描、只差 4px 与 6px 也能过，而同形态差 2px 在战斗节奏里不可辨。**结构差异在任何距离、分辨率、色盲与否下都可辨；宽度差要比较才看得出** |

| 11 | `dungeon.cp_threshold` 严格递增、每档 ≥1.3× 上一档，且 **≤ 该档预期总战力** | 门槛跳变，或门槛高于玩家可达战力（如 3900 对 3800 会直接卡死；孤锋崖 3900/3792 属技巧门槛，允许 1.3×） |
| 12 | **`hitstop_time_scale × hitstop_frames ≤ 1`**（代入 0.15 → 顿帧 ≤ 6 帧）。**展开式**：`(收身起始进度 − 后段窗口帧数) − hitstop_time_scale × hitstop_frames ≥ 2`，即 `(9 − 6) − 0.15h ≥ 2` | 三档 2/4/6 是**用满边界**（重档 gap 2.1 贴线，不是留白），改成 8 帧断言即挂。**写因果式而非 `hitstop ≤ 6`**：后者只给结果，前者给出来历——`time_scale` 若调低，上限会自动放宽，不会变成凭空卡人的常数。注意"公式自动跟上"≠"所有约束都跟上"：延后收身会挤到后段窗口，峰值速度须另验 |

### 9.6 视觉通道分离（防 Unity 叠加口径出事故）

Unity 有 `Material`（一个材质 3 个通道，都进 GBuffer）与 `AdditionalMaterial`（多材质各自进 GBuffer）两套口径：同一物体若同时挂基础材质与带 `Clear Coat` 的附加材质，会生成多余 GBuffer 通道；叠加到怪物身上时二者要么互相覆盖、要么叠加变白。**强制口径**：一个渲染器只允许一个 `Material` 槽，禁止 `AdditionalMaterial`；`Material.Enable Keyword Clear Coat` 全局关闭。由技术侧在 W7 加自动断言，不需美术逐件检查。

### 12.1 判据四问检查表（新增判据前必须逐条过）

本项目四次实证失败，根因同源。此后**任何新判据收进走查表或断言表之前**，先过这四问；答不上就不收，也不再另立新原则。

| # | 问 | 反例（已被本项目命中） |
|---|---|---|
| ① | **量的是"玩家感知量"还是"配置值"？** | 刀光曾以"屏幕面积 ≥3%"为准——竖直刀光在俯视角下的投影可能只为 0.5%，而玩家感知到的是刀光覆盖了角色剪影多少。已改为**遮挡比 ≤30%**（命中判定帧采样，帧内像素 alpha>0.1，按角色剪影包围盒计算，含刀身与手柄，透贴空白不计） |
| ② | **采样时刻写清了吗？** | 采样点曾在动画起始帧，而刀光在命中帧才可见——**测的是同一段，量的不是同一刻**。凡随时间变化的可读性，必须同时锁定"取哪一刻" |
| ③ | **能举出一个"正确做法会被它误杀"的证伪案例吗？** | 门槛曾以"每档 ≥1.7× 上一档"为准——看似严格，实则把 100→700（7.0×，**刻意断崖**，见 §5.1 注）判成违规，属误杀。已改为 `≥1.3×` 且 `≤ 该档预期总战力` 双条件 |
| ④ | **假通过时它会不会静默放过？** | 无敌可读性曾靠"参数正确"自证（2Hz、窗口 83ms 容不下半个周期）——**判据通过了，设计是坏的**。假失败会被人复查，假通过不会。每条判据必须配一个**负向用例**（故意做错的实现），负向用例不挂，则判据本身视为无效，不计入 Gate 1 |

> **负向用例强制**：判据 + 负向用例成对入库，缺一不可。实施成本约为判据本身的 30%，W4 排期已计入。这是本项目用四次返工换来的最贵的一条纪律。

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **一次只改一处**（只注入一个错误） | 一次注入两个错，挂了你也不知道挂在哪，用例失去定位价值 |
| 2 | **漏挂即废判据，不是调阈值** | 调阈值只是让这条用例通过，抓不住的错还在。判据失效必须换判据 |
| 3 | D5 对照组在正式样本**之前**跑，且必须同时消除**颜色、描边形态、入窗时机**三个通道 | 只消颜色不够——测试者会改用时序线索猜对，此时"通过"是伪的 |

**三个已写定的负向用例（示例，全 22 条同格式：注入什么 → 应报什么 → 没报说明什么）**

| 判据 | 注入 | 应报 | 没报说明 |
|---|---|---|---|
| C2 闪避无敌帧 | `invuln_start = invuln_end = 0` | 闪避成功 <10/10 | 无敌只在配表生效、战斗里没接上 |
| D5 形态可辨 | 两套描边只差颜色 | 通过率 <9/10 | 测试无效，测试者靠体态猜对 |
| E3 输入延迟 | 加 10 帧固定延迟 | >50ms | **两个时间戳同源、差值为 0** —— 最容易假通过的一条 |

### 12.2 硬约束检查时点

MVP 范围（1 角色 / 3–5 副本 / 1 主城 / **4–6 条修为线** / 1 套词条 / 1 Boss）的校验，**时点固定在"写进正文之前"**，不是发布前。本项目已两次出现"先形成方案、再被范围追认"（技能砍到 1 个、修为线砍到 3 条）——方案一旦排进排期，追认就变成默认放行。

### 12.3 固定常量错例表（跨域通用，写判据前对照一遍）

这张表是本项目十几轮返工里唯一可反复复用的资产。**五行里三行出自美术、一行配表、一行经济**——说明它不是某个岗位的能力问题，而是"写判据"这件事本身的默认失败模式。

| # | 错在哪 | 固定了什么 | 本该怎么定 |
|---|---|---|---|
| 1 | 受击帧数 12 / 13 来回改 | 把资产元数据写成配表常量 | 引用 `anim_clip_length` |
| 2 | `affix_pool` 存绝对战力值 | 锁死另一系统的基值 | 存系数 |
| 3 | 脉冲阈值写死 250ms | 固定毫秒，换频率即失效 | `1000 ÷ (2 × hz)` |
| 4 | 墨线 / 压边固定墨黑 | 固定颜色，换背景即失效 | 按环境亮度差推导 / 走副本参数 |
| 5 | 刀光"可见面积 ≥ 全屏 3%" | 固定占屏比例 | 占屏比依赖分辨率与 FOV → 改**遮挡比** |

**两句记法，两句都要（只记一句会漏掉第二类）**

> ① **依赖环境的量，写成推导式或环境参数**——管"换环境就失效"（墨线色、3% 面积、250ms）。
> ② **依赖窗口的量，先问窗口容不容得下**——管"这么短的窗口根本看不见"（83ms 里塞 2Hz）。一次明暗切换最少半周期；一段动画最少 1 帧；容不下就换表达方式。

## 13. MVP 验收标准

| 验收项 | 标准 |
|---|---|
| **首次闭环时长** | 新玩家 **≤15 分钟**完成一次完整闭环：落霞渡首通（6–8min）→ 营地升修为（3min）→ 战力从 120 涨到 390（3.2 倍）→ 再次进本 |
| 30 分钟节点 | 总战力 ≥380；已解锁铁砧窟；能说出"我下一步升哪条线" |
| 90 分钟节点 | 已通关铁砧窟；六线至少 3 条到 Lv3；装备至少替换 1 件 |
| 主线时长 | ≥7.5 小时（目标 7.5–9h）：六线 Lv10 + 5 本首通。**推导式**：主线 ≈ 有效副本次数 × 平均单局时长 × 重试系数；代入 26 × 12min × 1.35 ≈ 7.0h、26 × 13min × 1.4 ≈ 7.9h，得出 7.5–9h 区间。三个输入任何一项变化，必须重算而非沿用本行 |
| 整作时长 | ≥11 小时（目标 11–14h）：含词条毕业 |
| 手感 | **22 条**走查表 ≥**18/22**"可接受"；**C2** 闪避无敌帧、**D1a** 命中反馈 ≤3 帧、**D1b** 被打中 + 这一下多重（10/10）、**D2** 击退方向 8 向含斜向（10/10）、**D5** 霸体/无敌形态可辨五项必须通过。D5 判定口径：**B2 仅形态组为关键组**（同颜色、仅 `vfx_outline_style` 不同，5 人 × 10 张打乱图，每人 ≥9/10 且 ≥4 人达标；B2 不通过则正式结果不采信，B1 仅色差组只用于定位）；20 张须含铁砧窟橙底与雾隐竹海浓雾各 ≥2 张；W2 静态筛查 + W4 实战 3 分钟 ≥9/10。D1b-obs 只作观察。**另配 30 条用例（22 正向 + 24 A 类 + 6 B 类）作为 Gate 1 前置**：24 条 A 类注入错误应报错、6 条 B 类注入合法变体应通过；A 类任一漏挂即废判据重写，**不得调阈值** |
| 性能 | 集显轻薄本 1080p/30fps 稳定；独显 60fps |
| 稳定性 | 阻断级 bug 归零；崩溃率 0；20 次进出副本后存档不丢失不损坏 |
| 完整性 | 干净 Windows 机器可安装、可玩、可存档、可退出重进 |

**一句话验收**：一个新玩家在 **15 分钟内**完成第一次"打本→升修为→战力翻 3.2 倍→打更高本"，并在 **11 小时内**打通全部 5 个副本、六条修为线满级。

## 16. 关于"参考一梦江湖"的可行边界与转译方案（回应追加需求）

> 本节回应你 2026-11-15 的追加需求：喜欢其**复杂多线修为体系**（装备升级 / 宝石镶嵌 / 命格 / 特技 / 重铸 / 门派技能进阶等数十套）与**八技能全联动连招**（铃音以飓风为核心、沧海以大转盘为核心，其余技能皆为其服务）。本节只做**可行性判断与转译**，不改动前 15 章已冻结的范围。

### 16.1 你喜欢的其实不是"系统数量"，是三种体验

| 你点名的东西 | 它真正提供的体验 | 一句话 |
|---|---|---|
| 数十套并行养成 | **决策密度**：每次上线都有 6–8 个"可以推进一点"的入口，永远不会无事可做 | 不是"系统多"，是"选择多" |
| 8 技能围绕 1 个核心联动 | **构筑感**：所有按键服务于一个输出支点，玩家感到"我在搭建一台机器"，而不是"我在按键" | 不是"技能多"，是"有支点" |
| 多线长期叠加 | **长坡厚雪**：单点收益很小，叠加后质变，投入有复利感 | 不是"数值大"，是"能叠加" |

**结论**：这三种体验都可以在极小体量下被"近似"，但**深度无法被近似**。2 个技能做不出沧海那种 8 技能轮转的肌肉记忆；6 条线做不出 20 套系统的信息密度。这一点必须先说清。

### 16.2 真实体量对照（请先看清倍率）

| 项 | 一梦江湖 | 本项目 MVP | 倍率 |
|---|---|---|---|
| 团队规模 | 数百人（网易） | 3 人 | 约 1 : 100 |
| 累计投入 | 数十人年（2017 起持续迭代） | 0.9 人年（48 人周） | 约 1 : 100+ |
| 技能总数 | 9 门派 × 8 = 72 | 1 角色 × 2 | 1 : 36 |
| 养成系统 | 20+ 套（淬锋 / 浮生 / 阵法 / 装备熔断 / 势力秘籍 / 宗派技能 / 经脉 / 命格脸谱 / 威名豪杰 / 宝石 / 洗练重铸 / 特技 / 自创武学 / 行当培元 / 帮派技能 / 绝学 / 轻功强化 / 秘籍收集…） | 6 条修为线 | 约 1 : 3.5（按套数） |
| 内容周期 | 6 年以上持续更新 | 16 周 | — |

**换算**：把 72 技能压到 1 个角色 8 技能，仅动画就需 8 套 × 平均 3 条 = 24 条（现为 10 条），加 8 套特效、取消窗口系统、联动状态机与平衡周期，战斗模块从 10 人日涨到 70+ 人日；20 套养成每套 3–5 人日加 UI，需 300+ 人日。**合计 40–60 周、100 万元以上**——那不是 MVP，也不是 1–5 人团队能收口的项目。

### 16.3 逐系统转译表

| 原系统 | 提供的体验 | MVP 是否做 | MVP 等价物 | 后续版本 |
|---|---|---|---|---|
| 装备升级 | 稳定可预期的线性投入 | ✅ 部分 | 3 部位 × 5 品阶，品阶即"升级" | 强化等级（P2） |
| 重铸 / 洗练 | 随机性 + 追求更好的词条 | ✅ | 18 条词条随机 1–3 条（已含重铸的随机快感） | 定向洗练（P2） |
| 宝石镶嵌 | 配装决策 + 孔位规划 | ❌ | **词条第 3 条可免费替换 1 次/件**——保留"配装决策"，不加系统 | 镶嵌（P3） |
| 命格（脸谱 / 豪杰） | 长期收集 + 被动叠加 | ❌ | **名望线**：通关次数换确定性收益，同构于"收集换加成" | 命格（P3） |
| 特技 | 单个技能被"改造" | ❌ | **锋芒 / 势 资源环**（见 16.4），让 2 个技能互相改造 | 特技（P2） |

| 经脉 / 阵法 / 浮生 / 熔断 / 行当 / 帮派 / 自创武学 / 轻功强化 | 各自的收集与搭配 | ❌ | **不做**。这些是"数量"，不是"支点"，性价比最低 | 见 §14 P1–P3 |

### 16.4 连招联动的"2 技能"转译（零新增动画，+4 人日）

**规则**

| 环节 | 机制 |
|---|---|
| 生成 | 普攻每段**命中**累计 1 层「锋芒」（上限 3 层，6 秒未命中则清空） |
| 兑现 | **破锋**消耗全部锋芒：每层 +12% 伤害；≥2 层时附加"破韧"（对精英/Boss 有效） |
| 放大 | 破锋命中后获得 1 层「势」（持续 6 秒）；此时**回锋**升级为「破势回锋」：位移 +30%，末段无敌 5 帧 → 8 帧 |

**为什么这算"同构"而非"缩水"**：沧海的三爆是"地雷生成流珠 → 引爆兑现 → 呼啦圈放大"，泠音是"风场生成 → 流风状态兑现 → 绝学放大"。我们的三拍是**同一结构**：普攻生成 → 破锋兑现 → 回锋放大。玩家获得的"我在操作一台机器"的反馈是一致的，缺的只是**可轮转的技能数量**带来的熟练度深度。

**成本**：UI 资源条 1 人日 + 数值 1 + 逻辑 1 + 调优 1 = **4 人日，+0.3 万**，**0 新增动画、0 新增模型**（复用现有图集与刀光）。

### 16.5 修为线的"组合感"（零资产，+2 人日）

6 条线按相邻两两结成 5 组「共鸣」：任意两线达到同档位（如淬骨 Lv5 + 身法 Lv5）→ 激活 1 条被动（该组对应效果 +5%）。用 6 条线造出**5 组组合决策**，替代"20 套系统"提供的决策密度，成本仅 2 人日（纯数值 + 1 张 UI 图）。

### 16.6 四个选项与代价

| 选项 | 内容 | 工期 | 增量成本 | 保留了什么 / 失去了什么 |
|---|---|---|---|---|
| **A（建议）** | 保持现有 MVP，加入 16.4 + 16.5 两项转译 | 16 周 | +6 人日 / +0.4 万 | 保留"联动感 + 决策密度"的**近似**；不保留 8 技能的深度 |
| B | MVP 扩到 4 技能（1 核心 + 3 服务）+ 联动状态机 | 22–24 周 | +8–12 万 | 保留"多技能轮转"，仍只有 1 门派；排期翻 1.5 倍 |
| C | 分代：MVP 只验证"1 核心 + 1 服务"好不好玩，第二代再扩 | 16 周 | +0.4 万 | 最稳，但"复杂感"要等到第二代 |
| D | 照一梦做（8 技能 + 20 套养成） | 40–60 周 | 100 万+ | 不是 MVP，1–5 人团队不可行，**不建议** |

**我的建议**：**选 A**，把 B 的"4 技能"写进 §14 作为 MVP 通过后的第一优先。理由：你要的"联动"本质是**结构**（生成→兑现→放大），A 已经把这个结构给你了；B 加的是**数量**，而数量恰是 16 周装不下的部分。先用 A 验证"这个结构好不好玩"——如果好玩，B 才有意义；如果不好玩，B 只是把 4 个不好玩的技能做出来。

### 16.7 法律边界（再次强调）

- **可借鉴**：玩法逻辑本身——多线叠加、资源生成→兑现→放大的连招结构、以单一核心支点组织全部按键。这些属于玩法思想，不受著作权保护。
- **不可借鉴**：门派名、技能名、系统名（"命格""特技""重铸""经脉"等命名体系）、UI 布局与图标体系、数值表、美术素材、文案。
- **本项目的对应命名必须全部自建**：锋芒 / 势 / 共鸣 / 词条 / 修为线，均不与任何现有游戏重合。上线前仍需做一轮商标与名称检索。

| D1b / D2 判据 | D1b 只判"被打中 + 这一下多重"；方向归 D2（工程，8 向含斜向） | 击退方向是任意方向，4 个正轴向动画变体覆盖不了 45° 斜向；拿斜向测美术必挂且不公平。方向从此有人负责，但不归动画负责 |
| 无敌 / 霸体表现 | 无敌＝**纸白双边描边（内外各 2px、中间留空）+ 入窗高亮 1 帧**后回常态亮度，`vfx_pulse_hz`=0 不做脉冲；霸体＝赤色单边实描边 4px 常亮 + 入窗亮起 1 帧 | 回锋无敌窗口 5 帧（83ms）短于 2Hz 周期（500ms），脉冲在屏幕上看不到一次完整明暗变化——**是 5 帧窗口装不下，不是调参问题**。更早的"纸白闪帧 0.5 帧间隔"＝30 次/秒，超 WCAG 2.3.1 每秒 3 次上限，属光敏性癫痫风险，已整体作废 |
| 精英缩放 | 1.4× 且同步缩放受击盒 | 与体型比上限 1:1.4:2.2 一致；仅缩渲染体打不到 |
| 破锋 | 2 条独立剪辑 + 竖直刀光不落地 | 1.35 会把 12 帧霸体压到 9 帧，W4 必挂；地面形状通道留给敌人预警 |
| 地面形状通道 | 敌人独占 | 玩家特效一律不落地；哑刀"断崖一刀"地面大扇形是 E2 判据的唯一承载 |
