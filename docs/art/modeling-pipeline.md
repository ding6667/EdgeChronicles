## 0. 一句话与适用范围

**AI 生成的是"看起来对的网格"，进构建的必须是"能被绑定、能出描边、只有 1 个材质槽、面数在红线内"的网格。这两者之间隔着 7 道人工闸口，本文逐道写清谁做、用什么、产出什么、怎么判。**

适用范围：主角 + 3 Boss（第一批 4 件，见 `models_v1.csv`）。敌人 / 场景沿用同一链路，但闸口参数不同（面数、贴图尺寸、rig）。

**先说清一件容易误解的事**：GDD §风险表第 3 条写的「美术以买包改模 + 少量外包为主，不自行建模」是**旧路线假设**。本文档落地的是用户已拍板的新路线：**AI 文生 3D + 人工修**。买包改模作为兜底保留（某件 AI 生成不达标时切买包，不阻塞批次）。

## 1. 完整链路（7 道闸口）

每道闸口的格式：**谁做 → 用什么 → 产出什么 → 怎么判定通过**。任何一道不过，不进下一道。

```
[A] 提示词         ai_prompt.py 渲染 → 4 条 model_3d 提示词
      ↓
[B] 文生 3D        AI 生成原始网格（多材质槽 / 非流形 / 面数失控 / 无法线规范）
      ↓
[C] 重拓扑 + 拓扑清理   目标 10k–12k 四边面、水密、单一连通体
      ↓
[D] UV 重排        套用 UV_HERO / UV_HEAVY_A / UV_AGILE_B 三套既定布局
      ↓
[E] 材质槽合并     多槽 → 1 槽（本链路最硬的一步，见 §2.2）
      ↓
[F] 顶点色 + 法线   顶点色烘焙 / 手刷 → 法线按 50°/30° 重算
      ↓
[G] 导出 + 入库    .fbx + sidecar → Gate（G1–G16）
      ↓
[H] 绑定          2 套 rig（重甲 A / 敏捷 B）+ 12 条 Boss 动画
```

### 1.1 逐闸口规格

| 闸口 | 谁做 | 用什么 | 产出 | 判定通过 |
|---|---|---|---|---|

| **B 文生 3D** | 美术（我）执行，AI 出图 | 任一文生 3D 工具（Trellis / Meshy / Tripo / Hunyuan3D 类）；**工具选型未定，见 §6 U-1** | 原始网格（.glb / .obj）+ 生成原图 + 提示词全文留档 | 人眼首检三条：①双足直立人形、②独占剪影元素可辨、③无多足 / 触手 / 分层衣裙 |

| **G 导出 + 入库** | 美术（我）导，Gate 判 | Blender FBX 导出（参数见 §1.2）+ sidecar 手写 | `.fbx` + `.meta.json` | `python Tools/art/gate.py --root Assets/_Project/Art --json` 退出码 0（G1–G16） |

### 1.2 Blender FBX 导出参数（固定，不许各人各配）

| 项 | 值 | 为什么 |
|---|---|---|
| Transform | `Apply Scalings = FBX Units Scale`、`Apply Unit = ✅` | 缩放不烘进顶点（G15 的前提：缩放写 rig 根节点） |
| Transform | `Y` 向上、正面朝 `-Z` | Unity 坐标约定 |
| Geometry | `Smoothing = Face`、`Tangent Space` **不勾** | 切线由 Unity 自己算；本管线不用法线贴图 |
| Geometry | `Apply Modifiers = ✅` | 但重拓扑必须已 apply（modifier 不跨导出） |
| Armature | 勾 `Armature`、`Add Leaf Bones` **不勾** | 少 1 层无用骨骼 |
| 原点 | 脚底中点，`Object Transform = 0,0,0`（缩放同理） | Gate 的 G5 / 变换归零约定（IMPL-v2.0 §8.4） |
| 命名 | 物体名 = 资产 ID（`CH_HERO_PickBlade`） | G5 正则 `^CH_HERO_[A-Za-z0-9][A-Za-z0-9_]*$` |

## 2. 六个难点的解法

### 2.1 难点一：AI 网格非流形、面数不可控 → 重拓扑

**问题**：文生 3D 的出模普遍是三角面、面数从 3 万到 40 万不定、常有内部不可见面、浮空碎片、非流形边（一条边挂 3 个以上面）。

**解法（C 闸口）**

| 步 | 动作 | 工具 | 判定 |
|---|---|---|---|
| C-1 | 导原始网格，跑 `bmesh` 统计：三角面数 / 非流形边数 / 连通体个数 / 包围盒 | Blender Python（`bmesh`） | 统计数落到 sidecar（§3.2） |
| C-2 | 删内部不可见面 + 浮空碎片（按连通体面积排序，留最大 1 个，其余删） | Blender `Select Linked` + `Mesh → Clean Up` | 连通体个数 = 1 |
| C-3 | **重拓扑到四边面**：Quad Remesher 类工具，目标面数设 `tri_target / 2`（四边面数 ≈ 三角面数的 1/2） | Blender + 重拓扑插件（具体插件未选，§6 U-2） | 四边面 ≥90% |
| C-4 | 手工修重拓扑的坏区（关节、刃口、炉口内壁） | Blender 雕刻模式 / 网格编辑 | 关节处至少 2 圈环状边（§2.6） |
| C-5 | 三角化后计面数，对照 `tri_limit` | Blender `bmesh` 三角化统计 | ≤ `tri_limit` |
| C-6 | 复检水密 + 非流形 | `bmesh`：边界边数 = 0 且非流形边数 = 0 | 水密 |

**目标密度（有依据，不是拍的）**

| 资产 | GDD §8.2 区间 | 本批 `tri_target` | 本批 `tri_limit` | 依据 |
|---|---|---|---|---|
| 主角 `CH_HERO_PickBlade` | **8k–12k** | 10 000 | **12 000** | GDD §8.2 第 341 行「主角（3 套配色）… 面数 8k–12k」 |
| 3 Boss | **12k–15k** | 12 000 | **15 000** | GDD §8.2 第 343 行「Boss 孤锋崖守关者 … 12k–15k」；同时是 GDD §8.1 硬条款 ②「单角色 ≤15k」 |

> **主角 12000 与 `gate.py` G1 的 15000 不一致？—— 不冲突，是两个层级。**
> `gate.py` 的 `TRI_LIMIT_CHARACTER = 15000` 是**硬条款 ② 的通用红线**（对 `Character/Hero`、`Character/Enemy`、`Boss` 统一生效，见 `gate.py:124`）。
> 清单里的主角 `tri_limit = 12000` 是**GDD §8.2 的分品类建议区间上限**，比红线更严。
> **两者取更严者生效**：主角实际上限 = 12000（GDD §8.2），Boss 实际上限 = 15000（两者相等）。
> 即：主角走 12000，G1 的 15000 是通用天花板。**这是有意的双层口径，不是笔误。**

**四边面 ≥90% 怎么达到**：靠 C-3 的重拓扑工具本身（Quad Remesher 出的是全四边面网格），所谓 90% 是**给手工修 + 收口留的余量**——C-4 整形时会不可避免地产生三角面（刃口尖端、炉口内壁收口）。**所以 90% 不是"要努力达到"，而是"重拓扑后必然 ≥90%，手工修不许把它拉低到 90% 以下"**。这条由 Blender 侧脚本统计后回填 `quad_ratio`（§3.2）。

**为什么必须水密**：描边通道的遮罩 Pass 用 `Cull Back` 画不透明覆盖（`ECOutlineMaskPass.hlsl`）。非水密网格在开口处会漏出"洞"——遮罩上出现空洞 → 轮廓在该处断开 → **墨线在半路消失**。这是致命的视觉 bug，不是洁癖。

### 2.2 难点二：AI 一定生成多个材质槽 → 合并到 1 个（本链路最硬的一步）

**问题**：文生 3D 按语义分区自动分槽，典型输出 3–8 个槽（身体 / 甲 / 刃 / 腰带 / 头发各一）。硬条款 ① 只留 5 个共享材质槽、**每个模型材质槽数 = 1**（GDD §8.1 / `gate.py` G4）。

**为什么不能"就这么用多槽"**：多槽 = 多个 draw call + 多份材质实例。5 个共享材质槽的价值在于**全项目材质变体数恒定**，SRP Batcher 才能把 draw call 压住（`outline-urp14.md` §8.1「SRP Batcher ON 是 §8.2 CBUFFER 要求成立的前提」）。模型多带一个槽，就等于绕过硬条款 ①。

**解法（E 闸口 · 四步，按顺序做，不许跳）**

| 步 | 动作 | 具体操作（Blender） | 判定 |
|---|---|---|---|
| **E-1** | **选定唯一目标槽** | 按模型主体材质从 5 槽里挑 1 个：主角 / 哑刀 → `M_Cloth`；炉喉 / 碑守（重甲）→ `M_Rock`。**选定后写进 sidecar 的 `material` 字段** | 只有 1 个名字 |
| **E-2** | **把"分槽信息"转成"顶点色信息"** | 多槽的语义差异（甲 vs 布 vs 刃）本质是**色块差异**。做法：为每个原槽建一个顶点组（按槽分配的面选面 → 建组），再按组写顶点色（颜色取该槽在 §2.3 的语义色）。做完后各槽的**颜色语义已进顶点色** | 每个原槽都有对应顶点组，且组色已写入顶点色层 |
| **E-3** | **合并材质槽** | 选中全网格 → 把唯一的目标材质（`M_*`）设为 active → `Object → Join` 不适用（单物体），改用：删掉除目标槽外的全部槽（槽内面自动归到剩余槽）。**注意**：删槽不删面，面会落到 active 槽 | `usemtl` 分组数 = 1 |
| **E-4** | **贴图信息进三通道打包图** | 原各槽的 AO / Rough / Emissive 差异在 D–F 闸口已经烘进**同一张** `TX_*.png` 的 R/G/B（§2.4 的 UV 布局保证了各块不重叠，故各槽内容能共存于一张图） | 1 张贴图，**主角 2048 / Boss 1024**（GDD §8.2），RGB 无 alpha（G2/G3/G9） |

**关键点：合并的信息去哪了？** 不是"丢掉"，是**从"多材质槽"搬到了"顶点色 + 单张贴图"这两个载体**：
- 颜色 / 明暗差异 → **顶点色**（G14 判它存在，ΔE ≤8 判它准确）
- 粗糙度 / 自发光 / 环境遮蔽差异 → **贴图的 G / B / R 通道**

这就是为什么 G14（顶点色存在）在 `Character/**` 与 `Boss/**` 下是**失败级**判据：它是 E-2 是否真做了的证据。没顶点色 = 分槽信息在 E-3 时真的丢掉了。

**合并的粒度**：**整个模型合并成 1 个槽**，不是"按部位合并成 2–3 个"。硬条款写的是「任何模型材质槽数 = 1」，没有部位豁免。

### 2.3 难点三：没有顶点色 → 从哪来 + ±10% 怎么验

#### 2.3.1 顶点色从哪来（三条路，按优先级）

| 路 | 做法 | 适用 | 代价 |
|---|---|---|---|
| **① 从 AI 原图投影**（首选） | 用 B 闸口产出的生成原图（正视 / 侧视图），在 Blender 里做 `Project from View` 式的顶点色投射：相机对齐到正视 → 采样原图颜色 → 写入顶点色 | 造型与生成图一致的模型 | 需正视图 + 手工修背面色 |
| **② 手刷**（必做的补刀） | 顶点色模式直接刷；每块面刷成该块的语义色（§2.3.2 的 6 色 + 明度派生） | 所有模型的背面 / 遮挡面 / 块面边界 | 慢，但是**唯一能保证 ΔE ≤8 的路** |
| **③ 烘焙**（只在需要接触暗部时） | Cycles 烘 AO 到顶点色，再与 ①② 的结果相乘 | 炉口内壁 / 碑纹凹陷 / 关节褶 | 会把纯色压暗，**须在 ① ② 之后**，否则 ΔE 超差 |

> **不要用 ③ 打底**：AO 烘焙引入的是连续明度梯度，而「硬边平涂 / 块面内取值恒定」是本项目的形态语言。AO 只允许作为**块面内的轻微修正**（详见 §2.3.3 的例外条款）。

#### 2.3.2 ±10% 与 ΔE ≤8 的准确口径

两个判据不是一回事，别混用：

| 判据 | 出处 | 口径 | 谁来判 |
|---|---|---|---|
| **顶点色 ±10%** | IMPL-v2.0 §8.4「顶点色偏移 ±10% 以内」· GDD §8.1 硬条款 ①「副本差异一律用顶点色 ±10% 色相」 | **副本之间**的同一块面，顶点色的相对偏移量 ≤10%（这是"副本差异"的许可幅度，不是"与目标色差"） | 机器可算（§2.3.3） |
| **ΔE ≤8** | AD-03 文件头「ΔE ≤8」· IMPL-v2.0 §8.4「色域 ΔE ≤8」 | **与 6 色语义表的偏差**：任一块面的代表色与它所声明的语义色的色差 ΔE ≤8（CIE76 或 CIEDE2000 需定一种，§6 U-3） | 人判 + 机器算色差清单（§2.3.3） |

**两条都必须在。** ±10% 管「副本之间别跑偏」，ΔE ≤8 管「与语义色别跑偏」。只判其一会漏掉另一类问题。

#### 2.3.3 ±10% 具体怎么验（**这条 Gates 不做，谁在哪一步验——见 §3.1**）

**机器能算的部分**（Blender 侧脚本，一次跑完出 CSV）：

1. **逐块面代表色**：按顶点组（E-2 建的组）聚合顶点色，取组内均值 → 每块面 1 个 RGB。
2. **块内方差**：同组内顶点色的标准差。**硬边平涂要求块内取值恒定**，标准差异常高 = 刷出了渐变 = 违反形态语言。
3. **ΔE 清单**：每个块的代表色 vs 它声明的语义色 → ΔE 值。**输出 CSV，标出 >8 的块**。
4. **副本偏移**：同一资产的多套配色（主角 3 套）之间，同块的颜色偏移百分比 → 标出 >10% 的块。

**人判的部分**：ΔE >8 的块逐块看——是"确实要重刷"还是"这块本来就该用派生明度"（如炉口内壁用赭石的深色派生，ΔE 天然会大一些）。

**为什么不塞进 `gate.py`**：
- Gate 只解析 `.obj`（`gate.py:1053` 的 `_check_model` 只在 `ext == ".obj"` 时 `parse_obj`）。最终入库是 `.fbx`，**Gate 拿不到顶点色数值**。
- 即使改判 `.obj`，`gate.py` 的 `parse_obj` 也只解析 `v/vt/f/usemtl`，不读顶点色与顶点组。要判 ±10% 与 ΔE 需要**顶点组语义**（哪块面应该是哪个语义色），这个映射不在 Gate 的输入里。
- 结论：**这条由 Blender 侧脚本产出 CSV + 人判承接**，Gate 只负责 G14（存在性）这道最低门槛。**这不是遗漏，是分层：Gate 拦"完全没做"，脚本+人拦"做得不准"。**

### 2.4 难点四：UV 混乱 → 三套固定布局

**问题**：AI 网格的 UV 通常重叠、越界、或干脆没有。G6 要求「全在 [0,1]、每个岛距边界 ≥4px（`PADDING_PX = 4`，`gate.py:164`）、岛之间无重叠」。

**解法：不"重排成合理"，而是"套用三套既定布局"**。理由：3 Boss 里炉喉与碑守共用**重甲 A** 且共用**同一张 1024 贴图**——如果两人各展各的 UV，贴图就必须出两份，直接违反「单模型 1 张贴图」。

#### 2.4.1 布局的硬前提（来自 G6 与贴图上限）

- 贴图尺寸**按品类分，不是一律 1024**：**主角 2048**、**Boss 1024**、场景 512（唯一规定在 **GDD §8.2**）。
  > **修正记录**：本文件上一版写「主角也是 1024，依据 AD-03 §1.6 与 §3.1」——**那两处依据是错的**：AD-03 §1.6 讲的是**贴图格式口径**（通道与 alpha，不谈尺寸），§3.1 讲的是**星盘 4 系的形状语言**。两者都没有规定主角模型贴图尺寸。
  > **尺寸的唯一真值源是 GDD §8.2**（「主角 2048、Boss 1024、场景 512」），`gate.py` 的 G2 与 `models_v1.csv` 的 `tex_size` 均已按此对齐。
- 外边界 padding：**8px**（≥ G6 的 4px，留一倍余量吸收 UV 吸附误差）
- 块间 gap：**8px**（同理）
- 可用区：`[8, 1016] × [8, 1016]` = 1008 × 1008 px

#### 2.4.2 三套布局的像素圆整定义

**`UV_HERO`** —— 2×2 四块（头 / 躯干+臂 / 下肢 / 刃+挂件）

| 块 | 像素矩形 (x, y, w, h) | UV 矩形 (u0, v0, u1, v1) | 承载 |
|---|---|---|---|

### 2.5 难点五：描边依赖干净法线 → 法线怎么重算

**先纠正一个常见误解。** 本项目描边**不是**法线外扩（inverted hull），而是**屏幕空间遮罩法**（`outline-urp14.md` §2 的 4 个 Pass：遮罩 → 下采样 → 形态学膨胀 → 合成）。法线在这个方案里只有一个用途：

> **画"角色内部结构线"。** `ECOutlineComposite.shader` 里：
> ```hlsl
> edge = max(edge, (1.0 - dot(nC, nN)) * nc);   // nC = 中心像素视法线，nN = 邻域
> internal = saturate((edge - _ECOutlineEdgeThreshold) / max(_ECOutlineEdgeSoftness,1e-3)) * covC;
> ```
> `_ECOutlineEdgeThreshold = 0.35`，即 `1 - cos(θ) ≥ 0.35` → **θ ≥ 49.46°** 才出现内部墨线。

**所以"干净法线"的真实含义不是"光滑"，而是"法线在正确的折角处不连续"。** AI 网格法线乱的具体表现和后果：

| AI 网格的毛病 | 后果 | 修法 |
|---|---|---|
| 全平滑（smooth shading 一刀切） | **内部墨线全部消失**——折角处的法线连续了，`1-dot(nC,nN)≈0`，永远过不了 0.35 阈值 | 按 50° 设 sharp edge |
| 全硬边（每面独立法线，flat shading） | **每个面都出墨线**——整个人变成线团，形态语言崩掉 | 低于 30° 的合并为平滑 |
| 法线方向翻转 / 内外不一致 | 遮罩 Pass 的八面体编码出反法线 → 内部线位置错乱、正反面对不上 | `Recalculate Outside` + 手工修 |

**重算规范（F 闸口的法线部分）**

| 规则 | 值 | 依据 |
|---|---|---|
| 折角 **≥50°** | **硬边**（法线断开） | `1 - cos(50°) = 0.3572 > 0.35` → 稳过阈值，出内部墨线 |
| 折角 **≤30°** | **平滑**（法线连续） | `1 - cos(30°) = 0.1340`，远低于 0.35 → 不出内部墨线 |
| 折角 **30°–50°** | **不新建折角**（20° 禁区） | 阈值 49.46° 落在禁区边缘；建模误差 ±2° 就会让墨线在阈值两侧来回翻（同一块面在不同 LOD / 不同视角下时有时无） |

**Blender 操作（三步）**

1. `Object Data Properties → Normals → Shade Auto Smooth`，角度设 **50°**（Blender 4.1+ 是 `Smooth by Angle` modifier）。
2. 检查 30°–50° 区间：用 `Select Sharp Edges` 以 30° 选一遍，看是否有面落在 50° 以下却已断开——有则手工 `Merge` 回平滑。
3. `Mesh → Normals → Recalculate Outside`，再单独修炉口内壁 / 碑纹凹陷（这类凹面的法线朝里，会被 `Recalculate Outside` 翻错，**必须手修**）。

**导出注意**：Blender 的 sharp edges 会烘进 FBX 的顶点法线属性（FBX 无法线"平滑组"概念，法线是逐顶点烘死的）。所以 §1.2 导出参数里 `Smoothing = Face` 是必须的——设成 `None` 会丢法线。

### 2.6 难点六：3 Boss 复用 2 套 rig → 网格阶段要满足什么

**缩放已定**（写在 rig 根节点，不烘进顶点——G15 会判）：

| Boss | rig | rig_scale | 依据 |
|---|---|---|---|
| 炉喉 | 重甲 A | **1.0×** | `asset-spec-cards.md` §3.1 |
| 碑守 | 重甲 A | **1.15×** | 同上 |
| 哑刀 | 敏捷 B | **2.2×**（上限） | 同上 + GDD §8.1「哑刀 2.2× 为上限」 |

**为什么缩放必须写 rig 根节点而不是烘进顶点**：烘进顶点后，「炉喉 1.0× / 碑守 1.15×」就成了两个不同的网格尺寸，绑到同一个 rig 上会需要两套 bind pose → 2 套 rig 覆盖 3 Boss 的前提崩掉。写根节点变换则**网格是同一份尺寸基准**，只是摆到场上时乘不同系数。

**网格阶段（H 闸口之前）必须满足的四条**

| # | 要求 | 具体值 / 做法 | 判定 |
|---|---|---|---|
| **H-1** | **关节环线** | 每个可动关节（肩 / 肘 / 腕 / 髋 / 膝 / 踝）**≥2 圈环状边**（`models_v1.csv` 提示词里已写"预留至少 2 圈"）；膝与肘各再加 1 圈给弯曲缓冲 | Blender 里逐关节数环线；<2 圈则加 `Loop Cut` |
| **H-2** | **绑姿 = A-pose** | 双臂下垂约 45°、掌心朝内、双腿略分。**不用 T-pose** | 见下方理由 |
| **H-3** | **权重上限** | 每顶点**≤4 根骨骼**（Unity 默认 `Skin Weights = 4`）；归一化后权重和 = 1.0 | Blender `Weight Paint → Limit Total = 4` + `Normalize All` |
| **H-4** | **挂件刚性单骨** | 护盾（丛影）/ 刀 / 挂件**不混权重**，刚性绑单骨（GDD §8.1「挂件刚性单骨绑定、禁混权重」） | 每个挂件顶点权重只有一个 1.0 |

**为什么 A-pose 不是 T-pose**：`asset-spec-cards.md` §3.2 的 3 Boss 都靠**重叠在既有 rig 上的动画复用**；T-pose 绑姿在抬臂动作上会出现肩部塌陷（权重从水平位置摊开，一抬起就夹进去）。**这是本方案的选择，未经本机绑定实测，属 §6 U-4。**

**重甲 A 与敏捷 B 在网格阶段的额外差别**

| 项 | 重甲 A（炉喉 / 碑守） | 敏捷 B（哑刀） |
|---|---|---|
| 主体量 | 宽肩短臂（炉喉）/ 肩甲高耸（碑守） | 窄腰长臂 + 极长单臂刃 |
| 肩甲 / 炉口处理 | **随身体蒙皮**（碑形肩甲与胸腔是造型主体，不能当挂件） | 不适用 |
| 刃 / 单臂刃处理 | 不适用 | 刃**随臂骨蒙皮**（刃 = 臂的延伸），刃根与手腕的权重过渡要平顺，不能硬切 |
| UV 布局 | `UV_HEAVY_A`（上下二分） | `UV_AGILE_B`（刃优先二分） |

## 4. 贴图：四张源图 → 一张三通道打包图

**为什么必须分开做**：AI 生成不出"打包图"——它只会画一张看着好看的 RGB。所以 `ai_prompt.py` 里另立了 `tex_src_3d` 模板，**一张语义一张源图**：

| 源图 | 语义 | 生成后入哪个通道 | 提示词要点（模板参数） |
|---|---|---|---|
| `_Base_SRC` | 基础色（块面明度分布） | **不入包**（供人工核对 + 顶点色采样参考） | `tex_channel=基础色`，`tex_palette=单色块面 + 至多 1 个强调块` |
| `_AO_SRC` | 环境光遮蔽（接缝 / 接触暗部） | **R 通道** | `tex_channel=AO`，灰度语义 |
| `_Rough_SRC` | 粗糙度（块面级常量） | **G 通道** | `tex_channel=Rough`，**硬边平涂 → 分块常量** |
| `_Emi_SRC` | 自发光（炉口 / 炉火橙 / 碑纹点亮） | **B 通道** | `tex_channel=Emissive`，无自发光区域为纯黑 |

**打包顺序是硬约定**（AD-03 §1.6 / GDD §8.1 / `gate.py` 的 `REQUIRED_CHANNELS`）：

```
TX_<ID>.png  (1024×1024, RGB, 8bit, 无 alpha)
    R = AO
    G = Rough
    B = Emissive
```

**打包方法**：三张源图 → 图像工具按通道合成（Photoshop 通道面板 / Krita / ImageMagick 均可）→ 输出 **RGB 三通道** PNG（**不能有 alpha，不能有 tRNS**，G3 会判）。

**验证**：`python Tools/art/gate.py` 的 G2（尺寸）/ G3（位深与通道）/ G9（无 alpha）三条会直接从 PNG 头读出来判。
