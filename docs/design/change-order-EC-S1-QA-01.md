- **派生阶位规则**（对 A33-2）：**`tier` = 该派生所属技能「派生效果」类型所占的阶位**。当前 8 条派生实际落在 **2 / 3 / 5** 阶——破势回锋在缚锋 2 阶、末跳翻倍与回响在 3 阶、其余 5 条在 5 阶。**"派生只能落在 3 / 5 阶"是错的。**

- **已落地**：IMPL §4.5.1「阶位不变量」段 + §4.5.3「模板只适用新增门派、冲突时以 §4.5.4 为准」+ §4.8.5 的 A33-2 改写 + §7 的 A33-3 收窄。

## 2. 待落地（裁定已定，改动归各正本 owner）

### D-01 · `hit_shape.angle` 是整角 —— ✅ 裁定

- **裁定**：**整角**。`angle` = 扇形张角（度），`angle ∈ (0, 360]`；`120` 就是 120°，不是半角。
- **依据**：v2.0 §3.4 的样例 `sector / radius 2.4 / angle 120` 对应重击破军，120° 整角是合理重击扇形；按半角解释会变成 240° 巨扇，与重击读感不符；工程与 QA 参考实现双方均为整角。
- **要改**：`IMPL-v2.0.md` §5 的 `hit_shape` 字段表补一句「`angle` 为**整角张角（度）**」；注释里删掉"半角"这个词。**工程与 QA 实现不用改。**
- **影响断言**：无（现有断言不依赖角度语义）。
- **谁复核**：engineering-lead（v2.0 归属）。

### D-02 / D-13 · `movement_curve.keys` 的量纲 —— ⚠️ **已由主理人用证据推翻并终裁**（初裁"归一化位移占比"**作废**）

- **终裁**：`keys[i]` = **逐帧速度（m/s，非归一化）**。**不写「Σkeys = 1」断言**——速度语义下速度之和不等于任何固定值，该断言没有意义。
- **终裁 A24**：`|integralDistance − distance| ÷ distance ≤ 5%`，`integralDistance = Σ(keys_i × dt_i)`，`dt_i = 1 ÷ 逻辑时钟频率`（取自 `global_tuning`）。
- **推翻理由（取证，不是口味）**：① 美术权威规格 `docs/art/asset-spec-cards.md` §1.5 写死「位移一律用 **m/s**，不用 m/帧」，且 `cv_spd` **不在 Data 表里**（位移由 `MP_HERO_*` 曲线资产驱动）——`movement_curve.keys` 是该资产的数据层表示，**单位必须与资产一致，中间不留换算层**（换算层正是量纲错误高发区）；② 若 keys 是归一化占比，则 `integralDistance = distance × Σkeys`，**`distance` 根本不进断言**，A24 退化成格式检查、丢掉对 `distance` 列的校验；keys 是速度时 `integralDistance` 独立算出，**A24 才是真断言**。
- **初裁为什么错**：只考虑了"A24 能否成立"，**没问"A24 要保住哪个量的校验"**——它保住了 Σ，却把 `distance` 挤出断言。判据的价值不在形式自洽，在于**拦得住错**。
- **已落地**：IMPL §1.3「位移曲线字段与 14 条曲线清单」（keys 口径 + 新 A24 + 14 条曲线清单）、v2.0 §5 的 A24 与 13 表行、v2.0 §3.1 的 `movementCurve` 字段。
- **与 D-11 的合流**：距离类判据一律以**米**书写，取数显式 ÷100（逻辑坐标是厘米定点）——QA 的工程约束成立，与 §3.2 击退三档（m / m·s⁻¹）同口径。


### D-04 · 受击 `hold` 的公式跨轴 —— ✅ 含义已定，**必须改同轴**

- **裁定（含义）**：`hitstun_hold_duration` = **受击硬直总长 − 受击剪辑占用的墙钟时长 − 顿帧占用的墙钟时长**，即"**剪辑播完、顿帧结束之后，角色仍不可行动的那一段**"。GDD §9.4 已有这个式子，**含义不再分叉**（"硬直扣掉剪辑与顿帧后的剩余" 与 "hold 段本身长度" 是同一个定义）。
- **裁定（必须改的一处）**：式中的 `anim_clip_length` 是 **C 轴（剪辑帧）**，`hitstun_frames` / `hitstop_frames` 是 **W 轴（墙钟帧）**，**跨轴相减非法**。`anim_clip_length` 必须先按 `clip_length_W = anim_clip_length × 60 ÷ anim_fps` **换算到 W 轴**再参与运算；换算后 `hold < 0` → **报错**（硬直档配错剪辑），不取 0、不截断。
- **依据**：治理规则 12「固定常量错例表」举的反例同款（跨轴比较只是碰巧通过）；换算后自洽性可验——受击剪辑 13 C 帧 @60fps → `clip_W = 13`，则 hold = 18 − 13 − 2×0.85 = **3.3** ✓、20 − 13 − 4×0.85 = **3.6** ✓、22 − 13 − 6×0.85 = **3.9** ✓，**三档同时成立**，反证受击剪辑就是 13 帧 @60fps；若改为 30fps 交付必须先换算，否则 hold 变负。
- **要改**：GDD §9.4 的 `hitstun_hold_duration` 派生式 + 同节断言 1（`hitstun_frames ≥ anim_clip_length` 同样是跨轴比较，改成换算后比较）；v2.0 §5 的相关注解。
- **影响断言**：GDD §9.4 断言 1；`hitstun_hold_duration` 派生列。
- **谁复核**：engineering-lead（GDD 与 v2.0 的技术断言段）。

### D-05 · 顿帧上限断言把收身写死为 9 —— ✅ 裁定：**参数，不是常数**

- **裁定**：**收身起始位置升为参数**（受击剪辑元数据 / `hero_base` 管线注入，**当前默认 C9**）；断言保持**因果式**并引用该参数，**9 只能是默认值，不能是常数**。同理，**后段窗口帧数 6 也不该写死**——它是击退曲线的派生量（`knockback_curve_frames` 的末段），从派生值读。
- **依据**：GDD §9.4 断言 12 的展开式 `(9 − 6) − 0.15h ≥ 2` 把收身写死；剪辑一旦从 C10 挪到 C12，硬编码实现会**静默算错**——**这正是 GDD §12.3「固定常量错例表」要防的那类错误，这次出现在断言自己身上**。
- **要改**：① 受击剪辑的收身起点作为元数据导出（管线注入，禁手填）；② 断言 12 的展开式降级为"举例"，并标注 `9 = 当前默认值`；③ 后段窗口帧数改读派生值。
- **影响断言**：GDD §9.4 断言 12；v2.0 §5 的同款注解。
- **谁复核**：engineering-lead。

### D-10 · A22 查不到 `dodge` —— ✅ 裁定：**`dodge` 是门派共有动作标签**

- **裁定**：**普攻与闪避是门派共有**（IMPL §1 开篇已写死），8 门派技能表里**没有闪避行**，所以闪避**没有 `entryTags` 行**；但闪避**可以取消进入任何技能**——这是门派共有的特权，不是某个技能的能力。因此 A22「`allowTags` 必须存在于某 `skill.entryTags`」**漏掉了门派共有动作标签**，v2.0 §3.4 样例里的 `dodge` 永远查不到 → **规范自己的样例被判非法**。
  → **A22 的判定集合 = 8 技能 `entryTags` ∪ {门派共有动作标签}**。
- **落地（二选一，推荐 B）**：
  - **A**：A22 文本里加 `{dodge}` 白名单（改动最小，但例外藏在断言里）。
  - **B（推荐）**：导表器**登记一条虚拟闪避行**（`id = dodge_action`、`entryTags = ["dodge"]`、无 `animClip` / `hitShape` / `phases`）→ **A22 一字不改即可通过**，且"闪避也能被取消进入"这件事在数据里可见。
- **补一条**：`dodge` 只出现在 `allowTag`（闪避没有可被取消的后摇），**不作为 `sourceTag`**。
- **要改**：v2.0 §5 的 A22 文本；IMPL §1.2 / §1.3 补一句门派共有动作标签的登记口径（**§1 不在策划当前 ownership 内，需 team-lead 指定 owner**）。
- **影响断言**：A22。
- **谁复核**：engineering-lead。
