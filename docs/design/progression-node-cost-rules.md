## 1. 校验判据 C1–C7（可执行）

| # | 校验 | 判定 | 级别 |
|---|---|---|---|
| C1 | 星盘值域 | `1 ≤ star_node.cost_eu ≤ 60`（EL-03 §1.1） | L1 导表静态 |
| C2 | 络脉值域 | `1 ≤ meridian.cost_eu ≤ 50`（EL-03 §1.5） | L1 导表静态 |
| C3 | **星盘同系单调递增** | 同一 `series` 内按 N1 → N2 → N3 排序，`cost_eu` **严格递增**（`n2 > n1` 且 `n3 > n2`），不等即 error，精确到 `node_id` | L1 导表静态 |
| C4 | **络脉同分支单调递增** | 同一分支下，分支 < 其叶；破脉的两个叶：破脉·省 < 破脉·连 | L1 导表静态 |
| C5 | 络脉拓扑序 | 枢纽 > 任意叶 > 任意分支 | L1 导表静态 |
| C6 | **推导式复算（禁手填）** | 导表器按 IMPL §4.8.2 / §4.8.3 的系数**重算全部 20 行**并与表中值逐行比对，**不等即 error**（沿用 EL-03「禁手填」口径：任何手填值与重算值不等即报 error） | L1 导表静态 |
| C7 | **不进战力** | 星盘 / 络脉的 `cost_eu` **不出现在 A38 `expected_power` 公式的任何一项里** | L2 跨表审计 |

**C3 的必要性**：EL-03 §1.10 的两表此前既没有 `cost_eu` 列、也没有递增校验；C3 是该缺口的正式判据。**校验规则只在此处定义一次**，工程侧实现后回填 EL-03 的断言表。

**C3 / C4 是构造性保证，不是"碰巧排成这样"**：IMPL §4.8.2 / §4.8.3 的系数已使相邻两阶的比值恒 > 1（星盘 ≥ 1.5），因此**新增节点或重排节点类型都不会破坏单调性**；C3 / C4 只是把这条性质钉成断言，防止有人手填出破例。

## 2. 消耗口径边界（为什么与修为线、名望、技传都不冲突）

| 系统 | 载体字段 | 单位 | 取值来源 | 材料池 | 解锁门槛 |
|---|---|---|---|---|---|
| 修为线 | `cultivation_level.cost_eu` | EU · **单级升级价** | 6 线 × 10 级固定序列 | 6 线专属材料 | 修为线 Lv |
| **星盘** | `star_node.cost_eu` | EU · **单节点单价** | **IMPL §4.8.2 推导式** | 星盘点 | `star_node.unlock_tier`（名望档 I–III） |
| **络脉** | `meridian.cost_eu` | EU · **单节点单价** | **IMPL §4.8.3 推导式** | 脉络点 | 分支无门槛；叶需对应分支；枢纽需 3 分支全亮 |
| 技传 | `tech_tier.cost_eu` | **谱份数**（**不是 EU**） | IMPL §4.5.4 的 1 / 2 / 3 / 4 / 6 | 锋谱·八式 | 技传阶位 |
| 手札 | `specialty.cost_eu` | EU | 落数据层（EL-03 §1.4） | 秘札页 | — |
| 名望 | **无 `cost_eu` 语义** | — | `fame_source` 计数驱动 | **不消耗任何材料** | — |

**三条边界（不可越过）**

1. **同单位、不同量纲。** 星盘 / 络脉的 `cost_eu` 是"买**一个节点**要多少"，修为线的 `cost_eu` 是"升**一级**要多少"。两者单位同为 EU，但**不是同一规格**：**不得跨表相加、不得互相折算、不得用其中一套的序列去推另一套**。星盘 / 络脉**不引用**修为线的 10 级消耗序列。
2. **取值重合不是同一规格。** 两个体系里出现同一个数字只说明量级接近。**跨表不比较、不合并、不去重**；唯一性按"一个字段在一个表里只描述一件事"判定。
3. **名望是计数轴、星盘是解锁轴，两轴正交。** 星盘节点的**解锁门槛**是名望档（`star_node.unlock_tier` = 1–5），**消耗**是 EU（星盘点）：**名望点数不能直接买节点，EU 也不能抬高名望档**。名望**不消耗任何材料**（IMPL §4.3 材料总表：名望计数 = 无（通关计数）），因此名望与节点消耗**不存在口径冲突**。

## 3. 与战斗断言的关系（写死，不可改）

- 星盘 / 络脉**加战力 = 0**：两表的 `cost_eu` **不进 A38**、**不影响**任何战斗断言（伤害、帧数、层数、窗口、CD 全部与 `cost_eu` 无关）。
- 改 `cost_eu` **只改**"点数怎么花"（玩家在节点之间的取舍顺序），**不改**任何战斗效果。
- 因此：**不得为了"让数值有意义"而改动 IMPL §4.8.2 / §4.8.3 的「效果」列或「类型」列**——那两列才是战斗语义，`cost_eu` 反过来被它们决定。

## 4. 边界与反例（防止误改）

| 误改 | 为什么不行 |
|---|---|
| 把星盘某节点消耗调到与同系前节点相同 | 破坏 C3 的严格递增；该节点的"更晚解锁 + 改规则"定位不变，价不该更低 |
| 把络脉枢纽的消耗调到低于某个叶 | 枢纽是全部分支的公共前置，必须贵于叶才符合"越晚越贵" |
| 复用修为线的 10 级消耗序列给星盘 / 络脉 | 那是"单级升级价"，与"单节点单价"量纲不同（§2 第 1 条） |
| 让星盘 / 络脉的 `cost_eu` 进入 A38 | 两套系统加战力 = 0；进 A38 会凭空多出第二套战力口径 |
| 把技传的谱份数当 EU 与本表相加 | 技传的单位是**谱份数**，不是 EU（§2 表） |
| 给手札与络脉都加"锋芒上限 +1"并把上限写成 7 | 上限类按 A39「上限类取最大」合并，**多来源不叠加**；锋芒上限 5 → 6 的养成来源**只有手札特技**（IMPL §4.8.3 已写明） |
| 把星盘 / 络脉的 `cost_eu` 当成"战力"显示在养成面板 | 两表不加战力；面板上的战力只来自 A38 口径 |
| 在 IMPL §4.8 与 EL-03 §1.10 各写一份 20 个数字 | 立刻变成第二个真值源；**数值只在数据层，推导式只在 IMPL，判据只在本文件** |
