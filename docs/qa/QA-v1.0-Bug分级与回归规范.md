## 0. 分级原则

**不用主观形容词分级。** 禁止出现"有点卡""轻微""严重""基本能用"这类描述——它们在两个人之间不可复现。
分级只由下面 4 条**可观测**的轴决定，每条轴都能被机器或录屏判定。

| 轴 | 判据（全部为客观事实） |
|---|---|
| **A · 数据安全** | 是否造成存档损坏、资源凭空生成 / 丢失、Boss 阶段机进入未定义状态？ |
| **B · 判据违反** | 违反了哪条判据？是否一票否决项（WC-02 / WC-03 / WC-06 / WC-13）？是否只在人眼项上违反？ |
| **C · 手感可读性阻断** | 是否使某条一票否决判据在**运行时**失效（不是数据层，是玩家实际感受不到）？ |
| **D · 复现环境** | 必现 / 仅特定场景 / 仅特定机型或帧率 / 仅特定存档版本或分辨率？ |

## 1. Bug 分级标准

| 级别 | 判定条件（满足任一即入级，按最高级定级） | 处置 |
|---|---|---|
| **S0 · Blocker** | A 轴命中：存档损坏 / 读档失败未报错 / 资源凭空生成或丢失 / Boss 进入未定义阶段状态机 | 立即停止合并；必须同时补一条负向用例（回归用例） |
| **S1 · Critical** | B 轴命中一票否决判据，或 C 轴命中（一票否决判据在运行时失效） | 当前 Gate 不通过；必须补负向用例 + 人眼项复现记录 |
| **S2 · Major** | B 轴命中普通自动判据（可脚本判定） | 当次提交内修复；必须补负向用例 |
| **S3 · Minor** | 只违反人眼项（HP-xx），或数值有偏差但不违反任何已登记判据 | 登记后转后续修复处理；不阻断 Gate，但必须留下可复现记录 |
| **S4 · Environment** | 仅在 D 轴的特定环境下出现，且不违反任何已登记判据 | 必须写明机型 / 帧率 / 分辨率 / 存档版本与完整复现步骤；**无法复现的不得入级**，单列"待复现" |

### 1.1 定级的三条纪律

1. **一台设备上的"只在低端机型出现"不等于不可复现。** 必须在**最低支持机型**上复现；确实无法复现的，进"待复现"池，不占 S1–S4。
2. **同一根因不重复分级。** 一个根因引发 20 个现象，只开 1 个 Bug，其余作为"关联现象"挂在同一个 Bug 下。
3. **"违反断言"与"违反手感"分开记。** 数据层绿但运行时错的，必须记 C 轴（S1），不能因为"断言全绿"就降级——**永远报绿的断言比没有断言更危险**。

### 1.2 不入级的两类（必须单列，不许混入 S 级）

| 类别 | 处理 |
|---|---|
| **判据缺陷** | 判据本身量错了对象 / 缺量纲 / 阈值无来源 → 登记到 `KnownSpecConflicts`（`References.cs`），走规格裁定，**不得当成产品 Bug 修** |
| **规格冲突** | 判据与被测规格互相矛盾（如 A33 与 §4.5.4）→ 登记为 D-xx 冲突，交主理人 / 策划裁定 |

> 判据缺陷与产品 Bug 混淆的代价：为了让"红"变"绿"，会去改**正确的产品实现**。这是本项目明令禁止的。

## 2. 回归策略

### 2.1 分层

| 层 | 内容 | 触发时机 | 耗时量级 | 红了的含义 |
|---|---|---|---|---|
| **L0 · 提交级** | EditMode 全量：架构守卫 + 8 项冒烟（判据侧）+ 目录完整性 + **24 条 A 类 + 6 条 B 类负向用例** | 每次提交 | 秒级 | 判据或夹具被改坏 |
| **L1 · 合并级** | PlayMode 全量：战斗 × 养成联动矩阵 + 生产契约 8 项 | 每次合并到主干 | 分钟级 | 生产实现与判据不一致 |
| **L2 · Gate 级** | 人眼项 6 条 + 混合项 7 条的人眼部分 + B2 关键组 + **D5 对照组先跑** | 每个 Gate 一次 | 小时级 | 手感 / 可读性不达标 |
| **L3 · 修复级** | 回归用例：每条已修 Bug 对应的那一条负向用例 | 每次修 Bug | 秒级 | 修复没有真正堵住根因 |

### 2.2 强制规则

1. **每个已修 Bug 必须落一条负向用例**（A 类或 B 类），写进 `CriterionCatalog.NegativeCases` 或补充注入表。没有回归用例的修复**不算修完**——它只是把症状藏起来了。
2. **L3 回归用例必须在修 Bug 的同一个提交里加入**，不得事后补。
3. **L2 的 D5 对照组必须先于 B2 关键组跑**。对照组不合规时，B2 的结果无效（此时 B2 的"通过"是伪的）。
4. **人眼项的通过结论只认带协议编号的录屏记录**。没有录屏、没有机位 / 慢放记录的，一律记为"未测"，不许口头通过。
5. **L0 / L1 出现"契约未实现"导致的红** → 按**未实现**记，不按"失败"记；但**不允许跳过**，必须让它是红的。

### 2.3 回归用例的两种形态

| 形态 | 用在哪 | 例 |
|---|---|---|
| **A 类（灵敏度）** | Bug 是"注入一个错误"的形态：数据写错、判定写错、阈值越界 | 闪避无敌窗置零 → 判据必须报错 |
| **B 类（特异性）** | Bug 是"判据误杀了一个合法实现"的形态 | 60fps 合法击退被帧率依赖的判据误杀 |

> B 类回归用例的收录原则：**必须写清"哪条合法设计会被误杀"**。写不清楚的，说明这条用例不该存在。

## 3. 禁止事项清单

以下动作**一律禁止**。它们都是"为了让测试变绿而把正确实现改坏"的常见形态。

### 3.1 禁止改判据以求绿

| # | 禁止动作 | 为什么禁止 | 正确动作 |
|---|---|---|---|
| 1 | 为了让测试通过而**修改阈值** | 阈值是判据的一部分；改阈值 = 改判据，且没人会注意到 | 重写判据并登记新的误判条件 |
| 2 | 为了让测试通过而**放宽断言**（改成 `>=`、去掉上界、加 `if (debug) return`） | 同上，且更隐蔽 | 同上 |
| 3 | 为了让测试通过而**改产品实现**去迎合一条量错对象的判据 | 把正确的实现改坏，换来一个假的绿灯 | 登记判据缺陷 → 走裁定 |
| 4 | **删改 / 跳过负向用例** | 判据失去证伪装置，从此永远报绿 | 负向用例是判据的一部分，不是测试的一部分 |
| 5 | 把 `Assert.Ignore` / `Skip` 当作**通过** | 假通过比假失败危险 | 契约未实现就让它是红的 |
| 6 | 在生产代码里写 `if (Application.isBatchMode) return;` 之类的**绕过** | 测试环境下与真实运行行为不一致 → 测了个假的 | 不允许 |
| 7 | 在生产代码里**复制一份判据阈值** | 两份阈值迟早分叉；分叉之后没人知道哪份对 | 阈值取自 `global_tuning` 或 `CombatSpec`（唯一真值源） |
| 8 | 在判据里写**裸常量**（方法体内的字面量） | 形成第三份真值源 | 一律走 `CombatSpec` |

### 3.2 禁止写坏判据本身

| # | 禁止动作 | 为什么禁止 |
|---|---|---|
| 9 | **跨量纲相减 / 相比**（帧 − 米、m/帧 ÷ m/s） | 结论永远是假的 |
| 10 | **让帧号参与算术** | 帧号只用于标识对象；时间量用 `T_xxx`（elapsed 时刻，t=0 在命中帧） |
| 11 | 把**区间写成开区间**（该含端点却用 `<` `>`） | 恰好落在规格边界上的合法取值会被误杀（见 NC-B06） |
| 12 | 把**频率 / 时长阈值写死**而不是写成推导式 | 环境一变即失效（见 NC-B02：脉冲 250ms） |
| 13 | 把**帧率相关的量写成等式**而不是不等式 | 60fps 实现会被误杀（见 NC-B03：m/帧） |
| 14 | 把**判据量错了对象**（如用占屏比代替遮挡比） | 项目已经因此翻车三次（见 NC-B01） |

### 3.3 禁止写坏门控流程

| # | 禁止动作 | 为什么禁止 |
|---|---|---|
| 15 | 把"**人工确认**"作为通过判据 | 换个人结论就不同；必须给机位 / 距离 / FOV / 慢放 / 判定动作 |
| 16 | 先跑 B2 关键组、后跑 D5 对照组 | 对照组是"这次测试有效"的证明，不是补充 |
| 17 | 在**未修规格冲突**的情况下"两边都改一点" | 冲突被掩盖；正确做法是登记 D-xx 并裁定 |
| 18 | 用 `git commit` / `git push` 绕过评审直接推 | 规格卡的冻结流程是本项目的治理基础 |
| 19 | 把 S4（仅特定环境）写成"偶发""看运气" | 必须写清机型 / 帧率 / 分辨率 / 存档版本与完整复现步骤 |

## 4. Bug 报告模板

```
编号：BUG-<模块>-<序号>
级别：S0 / S1 / S2 / S3 / S4
违反判据：<判据编号>（无则写"不违反任何已登记判据"）
轴：A 数据安全 □   B 判据违反 □（一票否决 □）  C 手感可读性阻断 □  D 复现环境：必现 / 特定场景 / 特定机型 / 特定存档版本
环境：Unity <版本> · 平台 <Win 版本> · 机型与帧率 <写死> · 分辨率 <写死> · 存档版本 <写死>
前置状态：<技能 / 阶段 / 资源层数 / Boss 阶段 / 场景位置，精确到数值>
复现步骤：
  1. …
  2. …
  3. …
期望结果：<含量纲与时钟轴>
实际结果：<含量纲与时钟轴>
证据：<录屏文件名 / 截图 / 日志片段；人眼项必须带协议编号 HP-xx 与机位参数>
回归用例：<负向用例编号；本次修复同时新增哪一条>
```

> 报告里**期望结果与实际结果都必须带量纲与时钟轴**。只写"太快了""太重了"的报告会被退回。
