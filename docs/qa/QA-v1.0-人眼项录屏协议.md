## 0. 协议要解决什么

「**换个人来判结论也要一样**」是硬要求。只写"第三人称""看起来偏重""稍微有点卡"这类描述，换一个人判出来的结论必然不同——那它就不是 Gate，只是一个意见。

因此每条协议必须写死五件事：

| 要素 | 作用 | 不写会怎样 |
|---|---|---|
| 机位 | 相机相对被测物的方位 / 高度 / 俯角 | 同一个动作从不同角度看，观感不同 |
| 距离（m） | 被测物到相机的水平距离 | 透视强度随距离变，近看很重远看很轻 |
| FOV（°） | 视场角 | FOV 越大同一动作显得越小越弱 |
| 慢放倍数 | 录屏回放的降速倍率 | 60fps 原速看不清瞬时反馈 |
| 判定动作 | 测试者被要求做的**唯一**动作，且可二值化 | 收集到的是意见不是结论 |

外加**通过标准**（多少样本、什么比例算过）与**记录字段**（每次判定必须记什么，供事后复核）。

### 自检（已实现为自动化测试）

`Assets/_Project/Tests/EditMode/Criteria/HumanEyeProtocolTests.cs` 强制：

1. 每条人眼 / 混合判据都必须指向一个存在的协议编号（HP-xx）。
2. 每条协议的机位 / 距离 / FOV / 慢放 / 判定动作 / 通过标准 / 记录字段**一个都不能空**。
3. 距离 / FOV / 慢放 / 判定动作 / 通过标准里必须出现**具体数值**。
4. 协议文本中不得出现模糊措辞：`第三人称`、`看起来`、`明显`、`主观`、`适当`、`合理`、`大概`、`差不多`、`稍微`、`尽量`、`酌情`。
5. 协议编号不得重复。
6. 观察项 / 定位通道必须显式声明豁免负向用例的理由（WC-05 / WC-12 / WC-14）。

| 帧率 | 录制 60fps；回放慢放由各协议的「慢放倍数」栏规定 |
| 命名 | `HP-xx_技能或场景_第N次_日期.mp4`，编号与协议一致 |
| 完整性 | 每次判定必须保留**从预警出现到判定动作完成**的完整片段，不许剪掉等待段 |
| 环境 | 记录显示器型号与分辨率；换机器复测时必须注明 |
| 禁止 | 不许在录屏上叠加调试信息、HUD 数值或调试网格 |
